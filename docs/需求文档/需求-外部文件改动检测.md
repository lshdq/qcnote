# 需求：外部文件改动检测

## 背景与目标

应用当前打开文件后不再感知磁盘变化：文件被其他程序修改、删除或移动时，编辑器内仍是旧内容，用户保存会静默覆盖外部修改（或基于过期内容继续编辑）。目标是检测活动文档对应磁盘文件的外部改动，并按文档状态给出安全响应（自动重载 / 用户决策 / 删除提示），防止外部修改被无感覆盖。

## 功能描述

### 核心功能

1. **检测范围（仅活动文档）**
   - 只检测当前活动标签页对应文档的磁盘文件；未命名文档（无 url）不检测。
   - 非活动文档不做后台监测；切换标签到该文档时立即检测一次。
2. **检测机制（轮询 + 两级校验）**
   - 主窗口新增定时器（timer id = 7，现有 1–6 已占用），默认 1000ms 触发。
   - 第一级 stat 初筛：比较文件 mtime + size 与基线快照，未变则本轮跳过（开销极低）。
   - 第二级内容确认：stat 变化后读文件内容做 SHA-256，与 `Document::baselineHash()`（基线内容哈希）比较，消除 touch/mtime 变化但内容相同的误报。
   - 判定结果：`Modified`（磁盘内容与基线不同）/ `Deleted`（文件不存在）/ `Restored`（删除后文件重新出现）。
   - stat 查询失败（网络抖动、权限等非「确认不存在」错误）本轮跳过，不误报删除。
3. **立即检测触发点**
   - 切换标签（`activeDocumentChanged`）后立即 poll 一次活动文档。
   - 窗口从非激活变为激活（`WM_ACTIVATE`）时立即 poll 一次。
4. **响应策略（已与用户确认）**
   - 文档干净（无未保存修改）+ `Modified`：**自动重载**为磁盘新内容（静默，不打断用户）。
   - 文档脏 + `Modified`：弹三选框——重新加载（默认，丢弃未保存修改）/ 保留修改（继续编辑，保存时覆盖磁盘）/ 另存为…（先保住自己的修改）。
   - `Deleted`：**提示一次**（告知文件已不在磁盘，文档保持打开，保存时重新创建文件），不自动关闭。
   - `Restored`：清除删除提示状态；内容与基线一致则静默无动作，否则按 `Modified` 管线处理。
5. **防误报与抑制**
   - 自身保存/另存为/重命名/编码重载成功后同步刷新基线快照（同线程顺序执行，无竞态）。
   - poll 时对无快照或 url 与快照不符的文档自动建立快照（覆盖 openPath、saveAs、rename 路径）。
   - 脏文档用户选「保留」后，记录已决策的 stat 版本；同一版本不重复弹框，文件再次变化才重新决策。
6. **自动重载语义**
   - 重载走自动识别编码（BOM → 严格 UTF-8 校验 → GBK），不强制文档当前编码——文件已被第三方重写，重新识别更可靠；识别错可经既有「按编码重载」菜单纠正。
   - 重载后换行风格重探测、光标钳制到新内容长度、不置脏；Tab/标题/状态栏/编辑器/草稿清理全部走既有事件管线（`applyLoadedState` 传播链）。

### 边界与约束

- 单文档范围内一次最多弹一个决策框；模态期间（`UiLocked()`：对话框/菜单/文件对话框打开中）跳过本轮检测，天然防重入。
- 不新增「是否启用检测」设置项，默认开启。
- 删除提示只弹一次；删除后用户保存走既有 `LocalStorage` 原子写路径，自动重建文件。
- 最小化/失焦期间照常轮询（单文件 stat 开销可忽略）。
- 不改动 Tab 组件视觉（不做外部改动角标，留作后续扩展）。

## 输入输出

- **输入**：活动文档 url 的 stat（mtime/size）与磁盘内容 SHA-256；`Document::baselineHash()`。
- **输出**：
  - 干净文档：编辑器内容自动更新为磁盘新内容（含编码/换行元数据刷新）。
  - 脏文档：三选决策框（重新加载 / 保留修改 / 另存为…）。
  - 删除：一次性提示框。
  - 决策后的重载动作复用既有事件管线刷新全部 UI 与草稿状态。

## 非功能需求（性能/安全/兼容性）

- 每轮 stat 恰好一次（单文件）；内容哈希仅 stat 变化时计算，正常编辑会话零额外 IO。
- 检测器为 core 纯逻辑类，stat 查询与磁盘内容查询均注入，无 Win32/UI 依赖，可 Catch2 单测。
- 轮询间隔可经命令行 `--watch-interval-ms=<n>` 注入（测试钩子，生产默认 1000）。
- 回归红线：无文档/未命名文档/自测模式行为与现状完全一致；既有保存、另存为、重命名、编码重载、草稿、会话管线零语义变化。

## 依赖

- 既有 `core::Document::baselineHash()`（SHA-256，本就为磁盘外部修改判定设计）。
- 既有 `LocalStorage::read`（归一化内容读取）与 `core::sha256Hex`。
- 既有 `ui::DialogHost`（多按钮模态对话框）。
- 新增 `core/externalchangemonitor.h/.cpp`（纯逻辑检测器）。

## 验收标准

1. 打开干净文档 → 外部程序修改文件 → 最多 1s 内编辑器内容静默更新，无弹窗，文档仍干净。
2. 打开脏文档 → 外部修改 → 弹三选框：「重新加载」丢弃修改并载入新内容；「保留修改」继续编辑且同一版本不再弹；「另存为…」走另存为流程。
3. 删除活动文档文件 → 提示一次「文件已被删除或移动」，文档保持打开；随后保存可重建文件，保存后不再提示。
4. 删除后文件恢复原内容 → 无任何提示，状态复原；恢复为不同内容 → 按 1/2 管线处理。
5. 自己保存/另存为/重命名后不触发任何提示（基线快照已刷新）。
6. touch 文件（mtime 变、内容不变）不触发任何提示。
7. 非活动文档被外部修改 → 无任何提示/重载；切换为活动标签后立即检测并按 1/2 处理。
8. 切换标签、窗口重新激活时立即检测（不等下一轮询 tick）。
9. 现有 8 套 Catch2 单测与 7 个 verify 脚本全部通过，无回归。

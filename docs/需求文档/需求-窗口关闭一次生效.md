# 需求：窗口关闭一次生效

## 背景与目标

用户报告：点击标题栏关闭图标（X）需要点两次才能关闭应用，第一次点击无任何可见效果。

根因分析：`src/qml/Main.qml` 的退出流程中，`onClosing` 处理器先 `close.accepted = false` 拒绝本次关闭，再由 `beginExitCheck()` 在**无未保存修改**时置 `exiting = true` 并嵌套调用 `root.close()`。而 Qt 6 的 `QWindow::close()` 带重入保护（`d->inClose` 标志）：close 事件派发期间（`onClosing` 正在执行）再次调用 `close()` 会被静默忽略。于是第一次点击只置位了 `exiting`，窗口仍留在屏幕上；第二次点击时 `onClosing` 检测到 `exiting == true` 才放行关闭。

目标：关闭图标、Alt+F4、任务栏关闭、菜单"退出"在无未保存修改时**一次操作即关闭应用**；有未保存修改时的确认流程（保存/放弃/取消）行为保持不变。

## 功能描述

### 核心功能

重构 `Main.qml` 的 `onClosing` 处理逻辑：

1. `exiting == true`（退出已确认，未保存流程走完）：`close.accepted = true` 放行（维持现状）。
2. `uiLocked()` 为真（有模态对话框/菜单打开）：`close.accepted = false` 拒绝（维持现状）。
3. **无未保存修改：`close.accepted = true` 直接放行关闭**（替代原"拒绝 + 嵌套 close"的缺陷实现）。
4. 有未保存修改：`close.accepted = false` 拒绝本次关闭，置 `closeFlowDoc = firstModifiedDoc()`、`closeFlowIsExit = true` 并打开未保存确认对话框（逻辑等价于原 `beginExitCheck()` 的脏分支）。

同时移除 `beginExitCheck()` 函数（其干净分支成为缺陷点，脏分支并入 `onClosing`）。`doQuit()`、`continueExit()`、`finishCloseFlow()` 等其余流程保持不变——`continueExit()` 的 `root.close()` 在对话框按钮事件中调用，不在 close 事件派发内，不受 Qt 重入保护影响。

### 边界与约束

- 不改变未保存确认对话框的交互（三选：保存 / 放弃 / 取消；取消中止；多文档逐个确认）。
- 不改变 `uiLocked()` 屏蔽逻辑（模态对话框打开时忽略关闭请求）。
- 不移除对 Alt+F4 等系统发起关闭的拦截确认能力（有未保存修改时仍弹框）。
- 仅修改 QML 层逻辑，不涉及 C++ 核心代码。

## 输入输出

- 输入：用户关闭操作（点击标题栏 X / Alt+F4 / 任务栏关闭 / 菜单"退出"），以及当前文档未保存状态。
- 输出：
  - 无未保存修改：窗口一次关闭，应用退出。
  - 有未保存修改：弹出确认对话框；流程走完后应用退出或按用户选择中止。

## 非功能需求（性能/安全/兼容性）

- 关闭路径无额外事件循环往返（同步放行，不引入 `Qt.callLater` 异步延迟）。
- 兼容 Qt 6.11 `QWindow::close()` 重入保护语义（`d->inClose`）。
- 不引入数据丢失风险：有未保存修改时仍必须先经用户确认。

## 依赖

- 既有模块：`DocumentManager`（`hasUnsavedChanges` / `documentsModel`）、`unsavedDialog`、`uiLocked()`。
- 无新增第三方依赖。

## 验收标准

1. 打开应用（存在干净文档），点击标题栏 X 一次，应用立即退出。
2. 干净状态下按 Alt+F4 / 菜单"退出"一次生效。
3. 有未保存修改时点击 X：弹出"未保存的修改"确认框；保存 / 放弃后按原流程处理（多文档逐个确认后退出），取消则中止且内容保留。
4. 模态对话框（错误框 / 文件对话框 / 主菜单）打开时，关闭请求仍被忽略（维持现状）。
5. 现有 C++ 单元测试全部通过（`ctest`）。

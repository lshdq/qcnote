# 需求：标题栏窗口操作修复

## 背景与目标

自定义 Frameless 标题栏预期支持"空白区拖拽移动窗口"和"双击空白区最大化/还原"，但实际完全不生效（代码存在于 `TitleBar.qml` 的 `dragArea`，事件无法到达）。

**根因**：`DocumentTabs` 内部 `ListView`（`anchors.fill: parent`，默认 `interactive: true`）会接受其边界内所有左键按下（包括没有任何 Tab 的空白区），而 `TitleBar.dragArea` 声明在最底层，几乎被 Tab 条整体遮蔽，仅剩 4~8px 边缘缝隙，用户无法命中。

**次要差距**：当前实现最大化时直接禁用标题栏拖拽，与 Windows 原生行为不符（最大化时拖拽标题栏应还原窗口并继续拖动）。

## 功能描述

### 核心功能

1. **空白区拖拽移动**：在标题栏空白区（含 Tab 条无 Tab 覆盖的空白部分）按住左键拖动超过 4px 阈值后启动系统窗口移动（`startSystemMove`）。
2. **双击最大化/还原**：在标题栏空白区双击左键，最大化 ↔ 还原切换。
3. **最大化时拖拽还原并继续拖动**：最大化状态下拖拽标题栏空白区超过阈值 → 窗口还原（标题栏吸附到光标下方，水平锚点按按下位置比例保持，避免跳变）→ 继续系统拖拽。

### 边界与约束

- Tab 本身的点击激活、悬停、关闭按钮、键盘导航、溢出横向滚动行为保持不变。
- Tab 溢出撑满标题栏时无空白可拖拽（与 Chrome 等浏览器一致，属正常边界，记为已知限制）。
- 窗口移动/最大化属系统级交互，offscreen 平台无法自动验证，此类项由手动测试用例覆盖。
- 不修改边缘缩放命中区、`Win+方向` 贴靠等既有行为。

## 输入输出

无数据输入输出，纯交互行为修复。涉及文件：

- `src/qml/DocumentTabs.qml`：`tabList` 增加条件 `interactive`，附着 ScrollBar 同条件 `interactive` 联动（共享根属性 `tabsOverflow`，见决策 DEC-003/DEC-005）。
- `src/qml/TitleBar.qml`：`dragArea` 支持最大化拖拽还原。

## 非功能需求（性能/安全/兼容性）

- 不引入性能回退：条件 `interactive` 仅是一个布尔绑定。
- 不新增第三方依赖。
- 既有单元测试（3 个测试类共 46 个测试函数，含各类固定函数）全部保持通过。

## 依赖

- Qt 6.11.2（`Item.mapToGlobal()` 自 Qt 6.8 起可用，用于最大化还原时的光标定位）。

## 验收标准

1. 无文档打开时，拖拽标题栏空白区窗口跟随移动。
2. 双击标题栏空白区在最大化/还原间切换。
3. 打开 Tab 且未溢出时：Tab 激活、关闭按钮正常；空白区拖拽、双击生效。
4. Tab 溢出时：横向滚动、滚动条可用（无回归）。
5. 最大化状态拖拽标题栏：窗口还原并跟随光标继续系统拖拽，无大幅跳变。
6. 边缘缩放、`Win+方向` 贴靠、菜单与快捷键行为不变（无回归）。
7. 既有单元测试全部通过；offscreen 冒烟启动无 QML 错误。

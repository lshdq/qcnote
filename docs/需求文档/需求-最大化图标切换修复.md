# 需求：最大化图标切换修复

## 背景与目标

用户报告：窗口最大化后，标题栏"最大化"按钮图标没有切换为"恢复大小"图标。

根因分析：`src/qml/TitleBar.qml` 中按钮的 `glyph` 绑定
`root.window.visibility === Window.Maximized ? "restore" : "maximize"` 是正确的
（证据：最大化后再次点击按钮能正常还原窗口，说明 `visibility` 状态判断生效）。
问题出在 `src/qml/CaptionButton.qml` 的 Canvas：QML `Canvas.onPaint` 是命令式绘制，
不追踪 `onPaint` 内读取的 `root.glyph`；现有的唯一重绘触发器
`onPaintColorChanged: requestPaint()` 在 `maximize ↔ restore` 切换时颜色值不变，
不会触发重绘；Canvas 固定 10x10、按钮固定 44x40，窗口最大化不改变其尺寸，
因此没有任何机制触发重绘，图标停留在旧的最大化图形上。

## 功能描述

### 核心功能

- 窗口进入最大化状态后，标题栏最大化按钮图标立即切换为"恢复大小"图形（两个叠加矩形）；
- 窗口还原为普通状态后，图标立即切换回"最大化"图形（单个矩形）。

### 边界与约束

- 仅补充图标重绘触发，不改动按钮状态判断逻辑（`TitleBar.qml`）、图标绘制路径
  （`CaptionButton.qml` `onPaint` 内各 case）、无障碍名称切换（已由字符串绑定自动生效，
  不受 Canvas 重绘影响）；
- 菜单 / 最小化 / 关闭按钮的 `glyph` 从不变化，行为不受影响；
- 不改变 `CaptionButton` 对外接口（`glyph` / `accessibleName` / `showToolTip` / `clicked`）。

## 输入输出

- 输入：窗口可见性状态变化（`Window.Maximized ↔ Window.Windowed`）；
- 输出：Canvas 重绘为对应图形；无数据输出。

## 非功能需求（性能/安全/兼容性）

- 图标切换必须在状态变化的一帧内完成，无感延迟；
- 不引入额外定时器或轮询；
- 兼容深色/浅色主题（`paintColor` 既有绑定不变）。

## 依赖

- 无新增依赖；仅修改 `src/qml/CaptionButton.qml` 一个文件。

## 验收标准

1. 最大化（点击按钮 / 双击标题栏 / 系统快捷键 Win+Up）后，按钮图标变为"恢复大小"图形；
2. 还原（点击按钮 / 双击标题栏 / Win+Down / 最大化时拖拽标题栏）后，图标变回"最大化"图形；
3. 无障碍名称同步切换（"还原"/"最大化"），悬停工具提示跟随当前名称；
4. 现有单元测试（ctest）全部通过；offscreen 冒烟无 QML 错误；qmllint 对改动行无警告。

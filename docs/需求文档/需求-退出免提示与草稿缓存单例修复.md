# 需求：退出免提示与草稿缓存单例修复

## 背景与目标

两个问题：

1. **需求变更**：关闭 qcnote（X 按钮/Alt+F4/Ctrl+Q）时不再弹出「是否保存」确认。草稿缓存已保证未保存修改不丢，逐文档确认成为多余打断。退出语义改为**热退出**：直接退出，未保存修改（含未命名标签）经草稿缓存保留，下次启动自动恢复。
2. **缺陷**：用户实测（任务管理器强杀后重启）未命名标签页的草稿未恢复。根因（已实锤）：QML 引擎对拥有全默认参数构造函数的 `DocumentManager` 走「默认构造」而非 `create()` 工厂（Qt 6.11 `qqmlprivate.h` 单例构造模式选择顺序：默认构造 > 工厂），产生**两个 DocumentManager 实例**——QML 界面使用引擎默认构造的实例，而先被解析的 `DraftCacheManager` 经工厂链连接到另一个实例，文档信号永远到不了草稿管理器，草稿从不写盘。会话恢复此前「碰巧」正常（SessionManager 解析顺序靠后、连上了界面实例）。

## 功能描述

### 核心功能

1. **单实例根因修复**
   - `DocumentManager` 构造函数去掉默认参数：`explicit DocumentManager(QObject *parent);`，使 `std::is_default_constructible_v` 为 false → 引擎被迫走 `create()` 工厂 → 全程单实例。
   - 调用点适配：`create()` 内部 `new DocumentManager()` → `new DocumentManager(nullptr)`；测试中栈构造 `DocumentManager mgr;` → `DocumentManager mgr(nullptr);`。
   - 保持既有语义：构造自登记 `s_instance`（幂等）、析构置空。
2. **恢复激活规则**（缺陷次生修复）
   - `restoreDrafts()` 记录本次恢复的第一个文档；结束时若当前无活动文档（activeBefore 为空，如会话无文档、仅有未命名草稿）且存在恢复文档 → 激活首个恢复文档。修复「未命名草稿恢复后界面停留在欢迎页/空白内容区」。会话已有活动标签时行为不变（仍不抢占）。
3. **失焦即写**
   - `QGuiApplication::applicationStateChanged` → `ApplicationInactive` 时立即 `flushPending()`：把强杀丢失窗口从「最后 1 秒防抖」压缩到「失焦前 1 秒」。C++ 单测环境（QCoreApplication 无该信号）判空防御、不影响。
4. **退出免提示热退出**
   - `Main.qml onClosing`：去掉 `hasUnsavedChanges()` 拦截分支；无模态对话框打开时直接放行关闭。退出不再弹未保存确认。
   - 未保存修改去向：进程退出不触发 `closeDocument`（放弃清理不发生），防抖/失焦/aboutToQuit flush 已落盘的草稿保留 → 下次启动经 `restoreDrafts` 恢复为未保存状态。
   - 清理退出确认死代码：`continueExit`、`exiting` 标志、`closeFlowIsExit` 退出分支（标签页关闭确认流程保留：保存/不保存/取消三选不变，「不保存」仍清理该文档草稿）。
5. **QML 集成级回归测试**（此前盲区补齐）
   - 新增测试：加载真实 Main.qml → `newDocument` + 写内容 → **真实防抖计时器到期**（等待 ≥1.2s，不手动 flush）→ 断言草稿条目落盘（修复前红/修复后绿）。
   - 新增测试：重启场景（新进程/新引擎）后未命名草稿恢复为标签页且被激活。

### 边界与约束

- 标签页关闭（Ctrl+W/标签 X）的未保存三选确认**保留**（关闭 = 明确放弃，草稿清理语义不变）。
- 退出时有模态对话框打开仍拒绝关闭（uiLocked 语义不变）。
- 会话恢复的既有行为零变化（文件标签、光标、几何）；未命名文档仍不入会话（由草稿负责）。
- 用户并行开发中的滚动条改动（`EditorArea.qml`、`tst_editorintegration.cpp`、`docs/测试报告/`）不触碰。
- 诊断用临时 harness（`tests/test_window/tst_draftrepro.cpp` + CMake 条目）在验证完成后删除，不入库。
- `DocumentManager` 构造签名变化属编译期改动，影响面经 grep 全量枚举。

## 输入输出

- **输入**：用户退出请求（X/Alt+F4/Ctrl+Q）；任务管理器强杀前的编辑内容。
- **输出**：退出时无确认弹窗、直接退出；未保存内容经草稿保留并在下次启动恢复（含未命名标签，且恢复后直接可见可编辑）。

## 非功能需求（性能/安全/兼容性）

- 失焦 flush 为同步单文件原子写（MB 级文本可接受），不阻塞交互感知。
- 回归红线：标签关闭确认、冲突对话框、保存/另存为、编码转换、会话恢复行为全部不变；全量 ctest 无回归。

## 依赖

- Qt 6.11 `qqmlprivate.h` 单例构造模式选择规则（默认构造 > create 工厂）——本修复的依据与规避对象。

## 验收标准

1. 修改文件后直接点 X 退出：无任何弹窗，立即退出；重新打开：内容恢复为未保存状态（含未命名标签，恢复后标签可见且内容区显示其内容）。
2. 新建标签页输入内容，等待 ≥2 秒后任务管理器强杀：重启后该标签页带内容恢复并激活。
3. 新建标签页输入内容，**立即**（<1 秒）切换到任务管理器并强杀：因失焦即写，草稿仍恢复（失焦前 1 秒内的极端输入除外）。
4. 标签页关闭（Ctrl+W）有未保存修改时：仍弹三选确认；选「不保存」后强杀重启不恢复该文档。
5. 全量 ctest 通过（含 tst_windowclose 语义更新后的用例）。

# 需求：弹窗拖动

## 背景与目标

qcnote 当前所有应用内弹窗（QML `Dialog`）均固定在打开时的位置，不可移动。用户在窗口较小时可能被弹窗遮挡编辑区且无法挪开，不符合 Windows 桌面应用"对话框可拖动"的通用习惯。

目标：应用内所有自绘弹窗支持拖拽移动；同时将该规则沉淀到全局 `desktop-ui-design` skill，作为后续所有桌面 UI 设计的强制项。

## 功能描述

### 核心功能

1. **可拖动**：五个应用内弹窗（unsavedDialog、errorDialog、ctxMenuPromptDialog、reloadConfirmDialog、SearchDialog）的标题栏（header 抓取区）支持鼠标左键按住拖拽移动弹窗。
2. **边界约束**：允许弹窗身体部分移出主窗口，但标题栏把手必须始终保留在主窗口可视区内可抓回：
   - 水平：弹窗在窗口内的可抓宽度 ≥ 约 80px（`x ∈ [-(width - keep), parent.width - keep]`）；
   - 垂直：标题栏整体留在窗口内（`y ∈ [0, parent.height - 标题栏高度]`）。
3. **重开复位**：每次打开弹窗复位到默认位置（四个 Main 对话框居中；SearchDialog 按 DEC-002 顶部对齐 y=96），拖动仅在当次打开期间生效。
4. **resize 跟随与重约束**：未拖动时弹窗位置随窗口尺寸变化跟随默认位置（居中跟随）；已拖动后窗口 resize 时重新施加边界约束，保证把手仍在窗口内。
5. **skill 规则沉淀**：在全局 `desktop-ui-design` skill（`D:\Program\opencode\data\config\opencode\skills\desktop-ui-design\SKILL.md`）中新增"对话框和弹出层"小节与验收清单项，规则保持框架无关。

### 边界与约束

- 系统原生 FileDialog（打开/另存为）为 OS 窗口，天然可移动，**不改动**。
- 拖拽不得改变：模态性、Esc 关闭策略（`Popup.CloseOnEscape`）、footer 按钮角色与布局（WinLayout）、焦点链、点击遮罩不关闭行为。
- 拖拽仅支持指针操作，不要求键盘移动；但键盘路径不得因拖拽受损。
- 弹窗不可调整大小（本次仅做移动）。
- QML `Popup` 的 `anchors.centerIn` 与自由 x/y 互斥，改用 x/y 定位实现居中与拖动。

## 输入输出

- 输入：鼠标左键在弹窗标题栏按下并移动（合成事件亦可驱动，供自动化测试）。
- 输出：弹窗 x/y 实时更新并受边界约束；无持久化（不跨会话保存位置）。

## 非功能需求（性能/安全/兼容性）

- 拖动过程无明显延迟/抖动（DragHandler 直改 x/y，无动画）。
- 视觉与现状一致：标题栏文案、字号、颜色沿用现有 Material 标题样式，颜色取 `AppTheme` 语义 token，不新增硬编码色值。
- 标题栏须保留非颜色可辨识性（文本本身即把手线索，行为与系统对话框一致，不加特殊光标形状）。
- 回归风险控制：`tst_dialogstyle.cpp` 等既有测试同步适配并保持通过。

## 依赖

- 现有组件：`AppTheme`（语义 token）、`DialogButton`、Material 样式 Dialog。
- 全局配置：`desktop-ui-design` skill 文件（项目仓库外，改动影响所有项目）。

## 验收标准

1. 五个弹窗均可通过标题栏拖动；拖动范围符合边界约束（把手不丢失）。
2. 每次打开复位默认位置；未拖动时窗口 resize 弹窗跟随默认位置，拖动后 resize 重新约束。
3. 模态、Esc、footer、焦点、遮罩点击行为与现状完全一致（既有测试语义保持）。
4. `cmake --build build` 与 `ctest --test-dir build` 全部通过（含新增拖动用例）。
5. `desktop-ui-design/SKILL.md` 新增小节与验收清单项，表述框架无关。

# 需求：未保存修改临时缓存

## 背景与目标

应用当前的未保存修改只存在于内存：崩溃、进程被杀或意外关闭后全部丢失（会话恢复只记录 URL 与光标，不记录内容）。目标是为所有已修改（脏）文档建立临时缓存（草稿缓存）：编辑过程中防抖落盘，下次启动时把未保存修改恢复回来，最大限度避免工作丢失。

## 功能描述

### 核心功能

1. **草稿缓存管理器**
   - 新增 C++ `DraftCacheManager`（QML 单例，模式对齐 `SessionManager`：QPointer 防御、便携模式检测、可注入缓存目录的 C++ 可测构造、`create()` 工厂复用实例）。
   - 缓存目录：便携模式（exe 旁存在 `qcnote.portable` 标记，复用 `SessionManager::resolvePortableIniPath` 检测）为 `exe旁/drafts/`；否则为 `QStandardPaths::AppLocalDataLocation` 下 `drafts/`。
   - 缓存条目为每文档一个 JSON 文件 `<uid>.json`（QSaveFile 原子写），字段：version、url（未命名为空）、untitledName、content、cursor、lineEnding、encoding、hasBom、baselineHash（写入时刻基线内容指纹）、savedAt。
   - 条目主键为文档 uid（构造时生成的不可变 UUID），而非 URL：未命名文档无 URL，另存为后 URL 变化而 uid 不变。
2. **写入（防抖自动写）**
   - 经 `documentsChanged` 对比集合为文档补连信号（同 SessionManager 模式，覆盖 `newDocument` 等不发 `documentOpened` 的路径）。
   - `contentChanged` 且文档 modified → 1 秒防抖排队写（只重写发生变化的文档条目）；写失败 qWarning 静默容错，不弹错、不打断编辑。
   - `Document` 新增不可变 `uid()` 与 `savedContentHash()`（基线内容 SHA-256 指纹，供外部修改检测）。
3. **清理（对应已确认需求语义）**
   - `modifiedChanged` 变 false（保存成功 / 另存为 / 撤回到基线 / 按编码重载覆盖）→ 删除条目：统一按"内容回到基线"语义清理。
   - `documentClosed` 时文档仍 modified（关闭确认框选"不保存"的放弃路径）→ 删除条目：放弃即真丢，不恢复。
   - 正常退出无需专门处理：退出流程迫使所有脏文档保存或放弃，两条路径均已清理；崩溃则条目自然残留供下次恢复。
4. **恢复（启动时，会话恢复之后）**
   - `Main.qml` 启动时序在 `SessionManager.restoreDocuments()` 之后调用 `DraftCacheManager.restoreDrafts()`。
   - 有 URL 且磁盘内容哈希 == 条目 baselineHash（磁盘未被外部修改）→ **静默**把缓存内容应用为未保存修改（光标钳制恢复），条目文件删除，后续编辑按新文档 uid 正常再写。
   - 有 URL 但磁盘内容哈希不符（外部应用修改）或文件已不存在 → **弹窗提示**：一个对话框列出全部冲突条目，「恢复」= 以缓存内容覆盖为未保存修改（文件缺失时恢复为未命名文档），「丢弃」= 删除条目；对话框风格复用 MovableDialog/DialogButton。
   - 未命名条目 → 重建未命名文档（内容即缓存、沿用记录的显示名，编号器跳过占用号），标记已修改。
   - 损坏 / 版本不符的 JSON 条目 → 静默删除跳过，不阻断启动。
   - 恢复不改变会话恢复设定的活动标签。

### 边界与约束

- **崩溃丢失窗口**：防抖 1 秒，崩溃最多丢最后约 1 秒的修改。
- **放弃语义**：关闭时选"不保存"的文档不恢复（缓存已清理）；仅崩溃/强杀残留的缓存触发恢复。
- **缓存写失败**：尽力而为，qWarning 静默，绝不打断编辑。
- **单实例**：SingleInstance 已保证单实例运行，缓存目录无并发写。
- **便携模式切换**（增删标记/移动 exe）：缓存目录随定位规则变化，旧缓存自然失联不恢复（可接受，不迁移）。
- **恢复后状态**：恢复出的文档 modified == true，走既有脏文档关闭/退出保护流程，退出语义零改动。
- **明文存储**：缓存为本地明文 JSON，与被编辑文件同信任级，不做额外加密。
- 不新增"是否启用草稿缓存"设置项，默认开启。
- `LocalStorage` 存储层不感知缓存，零改动。

## 输入输出

- **输入**：启动时 `drafts/` 目录下的残留缓存条目（上次异常退出的遗留）。
- **输出**：
  - 运行中：脏文档内容+元数据的防抖缓存文件；
  - 启动时：静默恢复的未保存修改 / 冲突提示对话框 / 重建的未命名文档。

## 非功能需求（性能/安全/兼容性）

- 防抖 1000ms（CoarseTimer），只重写变化文档的单个条目；MB 级文本写压力可控。
- 缓存目录为用户数据目录（或便携目录），不写入被编辑文件所在目录；测试经构造注入临时目录，不污染真实配置。
- 回归红线：无缓存目录/条目时启动行为与现状完全一致；保存、另存为、关闭/退出流程等既有行为零改动。

## 依赖

- Qt 6 QtCore（QSaveFile、QJsonDocument、QCryptographicHash、QStandardPaths、QUuid，无新第三方依赖）。
- 既有 `DocumentManager`（文档生命周期）、`Document`（脏标记/基线）、`SessionManager`（便携检测静态函数）、`Main.qml`（启动时序与对话框体系）。

## 验收标准

1. 打开文件并修改，等待防抖到期后强杀进程，重启：文档重新打开且未保存修改恢复（标记为已修改），光标恢复。
2. 新建未命名文档输入内容，等待防抖后强杀进程，重启：未命名文档带内容恢复，标记为已修改。
3. 修改后正常保存（Ctrl+S）：缓存条目删除；再强杀重启：不出现恢复（内容已在磁盘）。
4. 关闭确认框选"不保存"（放弃）：强杀后重启不恢复该文档修改。
5. 修改并防抖落盘后，用外部程序修改原文件，重启：弹冲突对话框；选「恢复」→ 编辑器以缓存内容为未保存修改；选「丢弃」→ 使用磁盘内容。
6. 缓存条目被手工改坏（非法 JSON）：启动静默跳过，无弹窗、无崩溃。
7. 撤回到原始内容（modified 变 false）：缓存条目删除，强杀重启不恢复。
8. 既有单元测试（test_core 等）全部通过，无回归。

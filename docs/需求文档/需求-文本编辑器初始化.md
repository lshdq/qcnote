# 需求：文本编辑器初始化

## 背景与目标

新建项目 **qcnote**：基于 Qt 6 + QML（Qt Quick Controls 2，Material 风格）的 Windows 桌面文本编辑器。

本次任务目标：

1. 完成项目初始化与**纯文本编辑 MVP**（多标签文档）；
2. 为后续**格式扩展**（Markdown、JSON 等）与**存储扩展**（网络存储/获取）预留稳定的扩展点接口；
3. UI 设计遵循 `desktop-ui-design` skill 规则（四层窗口结构、主题 token、键盘与可访问性）。

## 功能描述

### 核心功能

**1. 文档管理（多标签）**

- 新建空文档标签（Ctrl+N），命名"未命名-N"，N 递增；
- 打开本地文件（Ctrl+O），FileDialog 支持一次选择多个文件；重复打开相同路径时激活已有标签；
- 保存（Ctrl+S，无路径时先弹另存为对话框）、另存为（Ctrl+Shift+S）；
- 关闭标签（Ctrl+W）、退出（菜单退出项 / 窗口关闭按钮）；
- 未保存状态：Tab 上显示 `●` 标记、窗口标题文件名后缀 `*`；关闭标签/退出时弹窗三选（保存/放弃/取消），取消则不关闭；
- 切换标签不丢失未保存内容（每文档独立编辑状态）。

**2. 纯文本编辑**

- TextArea 纯文本模式（`textFormat: PlainText`），等宽字体；
- 撤销/重做使用编辑组件自带能力；
- 编码：UTF-8；读取容忍 BOM（剥离，不进内容），写入不带 BOM；
- 换行符：加载时 CRLF/CR 归一化为 LF，记录文件原换行风格（CRLF/LF）；保存时按原风格写回；新文档默认 LF；
- 大文件（\>10MB）不做性能优化，允许卡顿，不作为缺陷。

**3. UI（按 desktop-ui-design skill，四层结构）**

- **顶部窗口栏（自绘标题栏，Frameless）**：最左菜单按钮（下拉菜单，菜单项显示快捷键）→ 文档 Tab 区 → 最右最小化/最大化/关闭按钮（窗口控制永不被 Tab 挤压）；
  - Tab：活动 Tab 白底、非活动 Tab 灰蓝底（语义 token）；含文档名称（超长省略 + tooltip 完整名）、未保存 `●` 标记、关闭按钮；溢出时横向滚动；方向键切换；
  - 标题栏空白处可拖拽移动窗口（`startSystemMove`），双击最大化/还原；窗口边缘可拖拽缩放（`startSystemResize`），保留系统贴靠（Win+方向）等原生行为；
- **第二栏工具栏**：新建、打开、保存（高频操作）；
- **内容区**：编辑区；无文档时显示欢迎空状态页；
- **底部状态栏**：光标行列、选中字符数/总字符数、编码（UTF-8）、换行风格（LF/CRLF）、文件完整路径（tooltip）；
- **主题**：`AppTheme` QML 单例提供语义 token（activeTab/inactiveTab/background/foreground/border/focus/error 等），Material 浅色/深色可切换；状态表达不得仅依赖颜色；
- **键盘**：焦点顺序 菜单 → Tab → 工具栏 → 编辑区 → 状态栏；菜单支持 Enter/Space/方向键/Escape（关闭并恢复焦点）；快捷键 Ctrl+N/O/S、Ctrl+Shift+S、Ctrl+W；
- **可访问性**：图标按钮有 accessible name；Tab 的 accessibleName 含未保存状态；焦点可见；
- 最小窗口尺寸 800×500；高 DPI 交给 Qt 处理；动画极简。

**4. 扩展点（仅接口与注册机制，不实现新格式/新存储）**

- `DocumentFormat` 抽象类：id、显示名、文件名过滤器、按文件名匹配；`PlainTextFormat` 为默认兜底格式；后续 Markdown/JSON 在 `src/format/` 新增实现类并注册；
- `DocumentStorage` 抽象类：按 URL scheme 匹配（`file`）；`read/write`；后续网络存储在 `src/storage/` 新增实现类并按 scheme 注册。

### 边界与约束（本期不做）

- 不做：Markdown/JSON 语法高亮与渲染、网络存储、查找替换、设置页、打印、国际化框架、最近文件、Tab 拖拽排序、拆分窗口、Win11 悬停最大化按钮的 Snap Layouts 弹出（自绘按钮不支持，记录为设计例外）；
- 仅支持本地文件（`file://` URL）；
- 应用显示名 `qcnote`，可执行文件名 `qcnote.exe`。

## 输入输出

- 输入：本地文本文件（UTF-8 / 带 BOM 的 UTF-8；CRLF/LF/CR 换行混合）；
- 输出：保存后的本地文本文件（UTF-8 无 BOM；按文件原换行风格写回；新文件 LF）。

## 非功能需求（性能/安全/兼容性）

- 目标平台 Windows 10/11 x64（Qt 6.11.2 MinGW 64-bit），不主动破坏跨平台可能性；
- C++ 核心逻辑（document/format/storage）必须有 QtTest 单元测试覆盖；GUI 用手工冒烟验证；
- 浅色/深色主题下 UI 元素可辨识，状态有非颜色线索；
- 构建工具链：CMake + Ninja（路径见 `.opencode/AGENTS.md`），无第三方依赖。

## 依赖

- Qt 6.11.2（Quick、QuickControls2、Test 模块），`D:\Program\Qt\6.11.2\mingw_64`；
- MinGW 64-bit（`D:\Program\Qt\Tools\mingw1310_64`）、CMake（`D:\Program\Qt\Tools\CMake_64\bin`）、Ninja（`D:\Program\Qt\Tools\Ninja`）；
- 无其他第三方依赖。

## 验收标准

1. 在 `build/` 目录完成完整构建，单元测试（ctest）全部通过；
2. 新建/打开/编辑/保存/另存为/关闭全链路可用；多标签切换时内容与未保存状态正确保持；
3. 未保存关闭弹窗三选行为正确（保存/放弃/取消），取消不关闭；
4. 带 BOM 的 UTF-8 读取不残留 BOM；CRLF 文件保存后换行风格保留；写入无 BOM；
5. UI 满足 desktop-ui-design 验收清单（MVP 取舍项除外）；
6. 扩展点接口存在且有单元测试锁定行为（格式匹配兜底、storage 按 scheme 分发、重复打开去重）；
7. git 仓库建立，需求/测试文档入库，功能代码完成首次提交。

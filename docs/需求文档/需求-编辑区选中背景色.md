# 需求：编辑区选中背景色

## 背景与目标

用户报告：编辑区选中文字的背景色是红色，不美观且突兀。

根因分析：`src/qml/EditorArea.qml` 的编辑区 `TextArea` 未设置 `selectionColor`，文字选区背景回落到 Material 样式默认值（系统调色板高亮色）。当前 Windows 配置下系统高亮色为红色系，因此选区背景呈现为红色。多光标选区（`AppTheme.multiSelection`）已是半透明蓝，不受影响。

目标：原生选区背景不再依赖系统色，改为与多光标选区一致的半透明强调蓝；选中文字保持原色；整体观感美观、不突兀。

## 功能描述

### 核心功能

1. `src/qml/AppTheme.qml` 新增语义 token：
   ```qml
   /// 原生文本选区高亮（半透明，叠于内容背景之上；与 multiSelection 同色，观感统一）
   readonly property color selection: dark ? "#336f9bff" : "#293564d4"
   ```
2. `src/qml/EditorArea.qml` 的编辑区 `TextArea` 补充两项属性：
   - `selectionColor: AppTheme.selection`（选区背景为半透明强调蓝）
   - `selectedTextColor: AppTheme.textPrimary`（选中文字保持原色；不设置时默认白色，在半透明淡蓝底上对比不足）

### 边界与约束

- 多光标选区 `multiSelection` 的取值与行为不变（两者同值、观感统一）。
- 不改动其他颜色 token；QML 中不引入散落硬编码色值，全部取自 AppTheme。
- 原生选区交互（鼠标拖选、Shift 选择、Ctrl+A、双击选词等）行为不变，仅视觉变化。
- 浅色/深色两套主题均适用。

## 输入输出

- 输入：用户在编辑区选择文本（鼠标拖选 / 键盘 Shift 选择 / Ctrl+A 等），以及当前主题状态（浅色/深色）。
- 输出：选区背景为半透明强调蓝（浅色 `#293564d4` / 深色 `#336f9bff`），选中文字颜色保持 `textPrimary`；切换主题时选区颜色随之即时切换。

## 非功能需求（性能/安全/兼容性）

- 纯静态颜色绑定，无性能影响。
- 两套主题下均保证选中文字可读性（半透明底不改变文字对比度的主要来源）。
- 符合项目约定：颜色集中于 AppTheme 语义 token，QML 禁止散落硬编码色值。

## 依赖

- 既有模块：`AppTheme`（`accent` / `textPrimary` / `dark` / `multiSelection`）、`EditorArea.qml` 的 `TextArea`。
- 无新增第三方依赖。

## 验收标准

1. 编辑区选中文字的背景为淡蓝色（浅色 `#293564d4` / 深色 `#336f9bff`），不再出现红色。
2. 选中文字颜色与未选中一致（`textPrimary`），可读性良好。
3. 多光标选区高亮颜色不变，且与原生选区视觉一致。
4. 主题切换（浅 ↔ 深）后选区颜色正确跟随。
5. 现有 C++ 单元测试全部通过（`ctest`）。

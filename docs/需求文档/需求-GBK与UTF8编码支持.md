# 需求：GBK 与 UTF-8 编码支持

## 背景与目标

当前编辑器仅支持 UTF-8（读取容忍 BOM，保存固定 UTF-8 无 BOM）。中文 Windows 环境下存在大量 GBK（CP936）编码的历史文本文件，打开此类文件会出现乱码，且无法转换保存。本需求为编辑器增加 GBK/UTF-8 双编码支持：打开时自动识别编码，识别错误可手动以指定编码重新加载；保存可指定目标编码，从而实现编码转换（如 GBK → UTF-8）。

## 功能描述

### 核心功能

1. **自动识别（打开）**
   - 无手工指定编码时，打开文件按以下策略自动识别：
     1. 带 UTF-8 BOM（EF BB BF）→ UTF-8（记录带 BOM）；
     2. 字节序列通过严格 UTF-8 校验（含纯 ASCII）→ UTF-8（无 BOM）；
     3. 其余 → GBK（按 Windows 代码页 936 解码；无法解码的字节以替换字符 U+FFFD 呈现，保证文件可打开）。
   - 识别结果（编码 + 是否带 BOM）记录到文档元数据，状态栏显示实际编码。
2. **手动切换（菜单栏入口）**
   - 主菜单新增「编码」子菜单，含两组操作：
     - **通过编码重新加载**（UTF-8 / GBK）：从磁盘按指定编码重新解码，磁盘内容不变，用于纠正识别错误；当前文档有未保存修改时，必须先经确认框确认丢弃修改才执行；重载后换行风格一并重探测，光标位置钳制到新内容长度内，不置脏。
     - **通过编码保存**（UTF-8 / GBK）：以指定编码立即保存当前文档（即编码转换，如 GBK 文件转存为 UTF-8）；当前编码项打勾标识。未命名文档（无路径）走既有另存为流程，另存为按已设置的编码写出。
   - 未命名文档禁用「通过编码重新加载」。
3. **编码转换**
   - 打开 GBK 文件正确显示后，通过「通过编码保存 → UTF-8」完成 GBK → UTF-8 转换；反向同理。
   - 保存为 GBK 时，若内容含 GBK 无法表示的字符（emoji、生僻字等），**保存失败并提示**（错误消息含首个不可编码字符及所在行号），不静默替换。
4. **BOM 处理（保留原状态）**
   - UTF-8 文件带 BOM：读取时剥离（不进入内容），保存时原样写回 BOM；
   - 无 BOM 的 UTF-8：保存不新增 BOM；GBK 无 BOM 概念（GBK 文件保存后转以 UTF-8 保存时，BOM 取该文档历史记录值，无记录则无 BOM）。
5. **会话记忆**
   - 会话文件按文档记录手动指定的编码（含自动识别结果），重启后按该编码打开；旧会话无编码记录时回退自动识别，兼容既有会话文件。

### 边界与约束

- 编码范围仅 UTF-8 与 GBK（GBK 采用 Windows 代码页 936（CP936，即 GBK 的 Windows 官方实现），完全兼容 GBK/GB2312 文件；界面统一显示 "GBK"），不做 UTF-16/UTF-32/Latin-1 等其他编码，GB18030 特有 4 字节扩展字符不在支持范围。
- 内存表示维持既有约定：内容一律 LF、无 BOM；编码与换行风格同为文档元数据，保存时写回。
- 「通过编码重新加载」以磁盘内容为准，重载后未保存修改被丢弃（有确认框保护）。
- 自动识别存在理论误判（GBK 字节序列恰好构成合法 UTF-8 时判为 UTF-8），由手动重新加载兜底，属预期行为。
- 新建文档默认 UTF-8、无 BOM。
- 网络存储（未来扩展）复用同一识别与编解码逻辑，但本需求仅实现本地存储（file://）。

## 输入输出

- 输入：本地文本文件原始字节（UTF-8 带/不带 BOM、GBK/GB2312/GB18030）；用户菜单操作（指定编码重新加载/保存）。
- 输出：
  - 打开：解码后的编辑器内容（QString）+ 编码元数据（encoding、hasBom）+ 换行风格；
  - 保存：按文档编码与 BOM 状态写回磁盘的字节流（原子写）；GBK 不可编码时保存失败 + 错误消息（含字符与行号定位）；
  - 状态栏：显示 "UTF-8" / "UTF-8 BOM" / "GBK"。

## 非功能需求（性能/安全/兼容性）

- 编解码与识别均为 O(n) 单遍处理，常规文本文件（数 MB）打开/保存无明显可感延迟。
- 保存失败提示必须先于磁盘写入发生（不可编码校验在写盘前完成）；写盘维持 QSaveFile 原子写。
- 兼容性：既有 UTF-8 无 BOM 文件读写行为不变；旧会话文件（无编码字段）可正常恢复；DocumentStorage 为内部接口，签名变更同步更新唯一实现 LocalStorage 与单元测试。
- 编码元数据随会话持久化，损坏/非法值静默回退自动识别，不阻断启动。

## 依赖

- UTF-8：Qt 6 内置 QStringConverter（Utf8），无新依赖。
- GBK：Windows 内置 NLS API（MultiByteToWideChar/WideCharToMultiByte，代码页 936），零第三方依赖、不依赖系统语言设置；实现层经实证本机官方 Qt 6.11.2 二进制包未包含 `big_codecs` 特性（QStringConverter::GB18030 不可用，见决策记录 DEC-009），故不采用 Qt 转换器实现 GBK；编解码封装于单一组件（src/platform/gbkcodec），未来跨平台时仅替换该组件。
- 无新增第三方依赖；不改动 C++ 模块注册方式与 QML 主题体系。

## 验收标准

1. 打开 UTF-8（带/不带 BOM）文件：内容正确，状态栏显示 UTF-8（带 BOM 显示 "UTF-8 BOM"），保存后 BOM 状态与原文件一致。
2. 打开 GBK 中文文件：内容正确显示中文，状态栏显示 GBK；直接保存仍为 GBK 字节，内容不变。
3. 菜单「编码 → 通过编码重新加载 → GBK/UTF-8」：以指定编码重新解码显示；有未保存修改时先弹确认框，确认后丢弃修改重载，取消则不动作。
4. 菜单「编码 → 通过编码保存 → UTF-8/GBK」：文件以目标编码写出（GBK→UTF-8、UTF-8→GBK 双向验证），状态栏编码更新，当前项打勾。
5. 含 emoji 的内容以 GBK 保存：保存失败，错误提示含无法编码的字符及行号，磁盘文件不被破坏。
6. 手动指定编码的文档重启恢复后仍按该编码打开；未指定的按自动识别打开。
7. 既有 UTF-8 行为回归：无 BOM UTF-8 读写、换行风格保留、会话恢复、另存为等全部既有测试通过。

### A3 Ctrl+D 重叠判定改排序+前缀 max end+二分 — 通过

- **修复核对**：`multicursor.cpp:293-335`——非空选区 [s,e) 提取 → 按 s 排序 → 前缀 max e 数组 → `overlapSkip(q)` 二分（lower_bound 于 `q+len`）判定 + 跳到 maxE。
- **语义等价性证明（复审重点，独立推演）**：
  - 判定等价：旧条件「存在选区满足 `q < e && s < q+len`」⇔ 排序后集合 {s < q+len}（恰为 lower_bound 前缀 [0, it)）中存在 e > q ⇔ `prefixMaxEnd[it] > q`。端点相接（e == q 或 s == q+len）两侧均判不重叠 → DEC-010「相邻可追加」语义保持；空选区不进结构（等价旧 continue）。
  - 跳过安全性：设 maxE 由选区 [s*, e*) 达成（s* < q+len, e* = maxE > q）。对任意 q' ∈ (q, maxE)：q' < maxE = e*，且 s* < q+len ≤ q'+len（len ≥ 1，targetText 非空）→ q' 与 [s*, e*) 重叠。故 (q, maxE) 内不存在可追加出现，跳过不改变「第一个不重叠出现」的结果——与逐字符推进实现输出恒等。
  - 前进性：idx = maxE > q ⇒ maxE ≥ q+1，无死循环。
  - 复杂度：O(m log m) 构建 + 每出现 O(log m)，总计 O((m+k) log m)，替换旧 O(k×m)。
- **最小性核实**：`multicursorAllOccurrences`（Ctrl+Shift+L）自带独立的非重叠收集循环（373-379，find+len 推进），不使用本判定——A3 未波及。✓

## 四、其他发现（复核后成立，按严重度排序）

### 4.1 [可选] WM_APP 自测钩子族门控不一致（P8 修复的同族缺口）

- **结论**：P8 仅为 `kMsgSelftestCommand`（WM_APP+7）加了 `g_headless` 门控，但同族的 `kMsgSelftestStage`（+2 菜单）/`kMsgTabsSelftestStage`（+3）/`kMsgDocSelftestStage`（+4）/`kMsgSearchSelftestStage`（+5）/`kMsgThemeSelftestStage`（+9）仍无形态门控——五个 stage 处理函数开头仅查 `g_mainWindow`（RunMenuSelftestStage 连窗口检查都没有），真实运行窗口收到外部 PostMessage 的这些消息时会完整执行 selftest 流程。
- **证据**：`src/main.cpp:1093`（RunMenuSelftestStage 无检查）、`:1268/:1509/:1903/:2439`（仅 `if (!g_mainWindow) return;`）、对照 `:3124`（+7 已门控）与 `:2775`（+6 有 dump 路径空防御）。
- **根因**：P8 修复按首轮问题字面范围（仅 +7）执行，未审视同族钩子的一致暴露面。
- **触发条件/放大路径**：本地任意进程 FindWindow 定位主窗口 + PostMessage(WM_APP+9) 等即可驱动真实运行窗口：切换主题、newDocument、向工作目录写报告文件（g_selftestThemeOut 等为空时用 cwd 默认文件名）。
- **影响**：与修复前 +7 的暴露面同级（本地进程才能触达、状态扰动而非数据损坏、单用户桌面应用）——故定可选，与首轮 P8 定级尺度一致；但 P8 的修复目标「真实运行窗口不被外部 WM_APP 驱动」未彻底达成。
- **建议**：五个 stage case 统一加 `SelftestModeActive() || g_headless` 门控（该聚合函数已存在，main.cpp:226）。不修复的影响：上述暴露面持续存在，与 +6/+7 的防御形态不一致，后续维护者难以判断哪些钩子是「仅测试形态」。

### 4.2 [可选] P5 超长输入无回归锁定断言

- **结论**：修复移除了 4096 字符截断上限，但测试增量（selftest 场景与单测）均使用短文本——若回归改回固定缓冲，现有测试不失败。
- **证据**：`src/ui/searchdialog.cpp` EditTextContent（动态读取）；`tests/verify-search-selftest.ps1` 输入均为常规长度。
- **影响**：截断回归（粘贴 >4096 字符后查找内容不完整）将无测试检出。属测试缺口，非生产缺陷。
- **建议**：selftest-search 增加一条「输入 >4096 字符文本后实时计数覆盖文本尾部子串」场景。不修复的影响：P5 行为处于无锁定状态（代码简单、风险低，故可选）。

### 4.3 [可选] A3 压力用例时间阈值检出力边缘

- **结论**：`REQUIRE(ms < 5000)` 的平方实现检出余量不足——60000 全重叠场景旧实现约 1.8e9 次选区比较（每次命中扫描前缀个选区），Release 下量级 1~3s，快机器上可能低于 5s 阈值而漏检性能回归。
- **证据**：`tests/test_search.cpp:477-495`（n=60000、阈值 5000ms）；新实现实测毫秒级。
- **影响**：若实现回退为逐字符推进且运行机器快，时间断言可能仍 PASS——但 nullopt 语义断言不受影响（正确性检出保留，仅性能回归检出弱化）。
- **建议**：阈值收窄至 500ms（新实现毫秒级，余量两个数量级）或 n 提升至 200000。不修复的影响：性能防退化敏感度弱，正确性防护完整。

### 4.4 [pre-existing 观察] 剪切路径剪贴板写失败仍执行删除

- **结论**：Ctrl+X（multicursorcontroller.cpp:573-594）中 `clipboardWrite` 返回值被忽略，写失败时仍执行选区删除（`ApplySelections(ReplaceRangesDescending(...))`）——「先写后删」无补偿，极端情况下剪贴板为空而原文已删。
- **证据**：`src/editor/multicursorcontroller.cpp:590-591`。
- **根因/时点**：修复前即如此（旧代码连 SetClipboardData 返回值都不看并泄漏 HGLOBAL）；P7 修复的「如实返回」正是消除此观察项的前提条件，属向正确方向推进。
- **不要求本轮修复的理由**：失败概率趋近零（OpenClipboardRetry 已覆盖主要失败模式；GlobalAlloc/Lock/SetClipboardData 连续失败仅剩剪贴板锁异常等系统级故障）；修复需要行为决策（写失败时剪切是否整体放弃）并引入行为变化需新一轮验证，超出收敛复审轮最小变更边界。建议与 P4/P6/P9 同列留档，后续迭代处置。

## 四、其他发现（经复核成立，按严重度排序）

**阻塞：无。应改：无。**

- [可选] 调用效率: onMouseMove 单次调用内 geometry() 重复计算 2~3 次 —
  证据(doclist.cpp:524-562 hitItem→geometry()、:552 hitScrollbarPart→geometry()、
  :446-453 惰性钳制最多再算一次) — 根因: 命中三函数各自独立调用 geometry()，
  无单次消息内复用 — 触发条件/放大路径: 面板可见 + 鼠标在客户区任意位置移动
  （main.cpp:5652-5654 无条件转发），每帧 2~3 次 O(n) vector 重建 + 堆分配；
  100 文档 @125Hz ≈ 250~375 次/秒 — 影响: CPU 占用可忽略（<1%），无正确性
  风险，偏离 guide「热路径复用计算」基线但与 TabStrip 既有模式同构（有意识的
  一致性设计，doclist.h 注释声明「三方共用同一几何源」） — 建议: 单次
  onMouseMove 内缓存一次 geometry 结果传给 hitItem/hitScrollbarPart（局部变量
  复用，不改变纯函数架构）；不修复仅持续微小开销，无累积。

- [可选] 一致性: 极窄窗口下 panelRect 截断值与 welcome 左内缩宽度口径不一致 —
  证据(doclist.cpp:343-345 panelRect 右界截断到 contentRect_.right 防御；
  main.cpp:1583 editorRect.left 用截断后 panel.right，:1585 setLeftInset 用
  未截断 widthLogical_) — 根因: 两处收缩基准取自不同变量 — 触发条件/放大路径:
  内容区物理宽 < Scale(widthLogical_)（约 < 240px@96dpi 的极窄窗口） — 影响:
  被 welcome computeLayout 的 contentW<=0 防御拦截（welcome.cpp:123-124 极窄
  不绘制），实际不可见，无用户可感知缺陷 — 建议: setLeftInset 传
  截断后逻辑宽或注释声明口径差异；不修复无实际后果（防御链已闭环）。

- [可选] 视觉自愈: 面板条目按下无捕获，拖出面板在编辑区（子窗口）松手时
  pressed 高亮残留 — 证据(doclist.cpp:594-601 条目分支无 SetCapture，对比
  :834-838 滚动条分支有捕获；:533-537 仅鼠标 move 再达组件时自愈，鼠标在
  Scintilla 上移动不产生主窗口 WM_MOUSEMOVE) — 根因: 无捕获则 up 被子窗口
  消费，主窗口收不到 — 触发条件: 按住面板条目拖入编辑区再松手（down 时文档
  已激活，仅按下态视觉残留） — 影响: 纯视觉（该行持续 pressed 叠色）至鼠标
  回面板/leave/失焦自愈；与 Tab 条既有同构模式一致（tabs.cpp:568-574 同款
  自愈，pre-existing 惯例非本次引入） — 建议: 条目按下也 SetCapture（对齐
  滚动条分支）或接受现状（与 Tab 一致）；不修复仅低频场景视觉瑕疵。

- [可选]（pre-existing 惯例顺带提示）showTooltip 工作区钳制用物理常量 300 未
  随 DPI Scale — 证据(doclist.cpp:1006 workRight-300 物理值；tabs.cpp:1087
  同款——系复刻 Tab 条既有手法) — 影响: 200% DPI 下右侧余量语义偏小（300 物理
  = 150 逻辑），tooltip 略早贴边换行，纯视觉微差 — 建议: 与 tabs.cpp 两处
  一起统一 Scale（属既有风格复制，非本功能缺陷，合并处理避免口径分裂）。

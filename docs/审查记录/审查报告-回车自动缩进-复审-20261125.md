## 复审重点 1：争议裁决独立核实（应改-1 误报裁决）——亲自对照 vendored 源码，结论与前两方一致

**「一次 UNDO 整体回退」成立，上轮应改-1 确为误报。** 独立证据链（全部亲自读取 vendored Scintilla 5.6.9 源码核实）：

1. **`Editor::NewLine()`（`vendor\scintilla\src\Editor.cxx` L3326-3370）**：
   - L3333 `UndoGroup ug(pdoc, !sel.Empty() || (sel.Count() > 1));` —— 非空选区或多光标时 undo 组激活；
   - L3336-3338 `ClearSelection()`（非空选区删除）与 L3343-3351 逐选区插入 `eol`（"\n"）—— **均在组内**；
   - L3355-3363 通知循环 `NotifyChar(ch, CharacterSource::DirectInput)`（L3357，→ SCN_CHARADDED）—— **仍在组内**（L3353-3354 注释原文「Perform notifications after all the changes as the application may change the selections in response to the characters」）；
   - L3370 函数体结束 `}` 处 `ug` 析构 —— **组此时才关闭**。SCN_CHARADDED 是同步通知（NotifyChar 在 NewLine 调用栈内直接回调宿主 WndProc），宿主补缩进 `SCI_INSERTTEXT` 发生在 `EndUndoAction` 之前。
2. **`UndoGroup` 是纯 RAII**（`vendor\scintilla\src\Document.h` L666-686）：构造 → `pdoc->BeginUndoAction()`，析构 → `pdoc->EndUndoAction()`；转发链 `Document::BeginUndoAction`（Document.h L476 inline）→ `CellBuffer::BeginUndoAction`（CellBuffer.cxx L1122）→ `UndoHistory` 完整。
3. **组内动作强制可合并**（`vendor\scintilla\src\UndoHistory.cxx`）：
   - `AppendAction` L266-269：`undoSequenceDepth > 0`（组内）时强制 `mayCoalesce = true`；
   - L273 顶层判定（L283 `!actions.types[targetAct].mayCoalesce → coalesce = false`，上轮审查引用处）**仅在 `undoSequenceDepth == 0` 时进入**；组内动作走 L311-314 非顶层分支——不看类型/位置，只看前一动作 `mayCoalesce`（组内动作恒为 true）→ 删除选区、"\n" 插入、补缩进插入全部并入同一用户操作；
   - `EndUndoAction` L344-352：`undoSequenceDepth` 归 0 时把最后一个动作 `mayCoalesce = false` 封组——**组关闭之后**的新动作才不能并入；上轮引用的该行为本身正确，但被错误地套在了组关闭之前发生的补缩进插入上。
4. **一次 SCI_UNDO 整段回退**：`StartUndo`（UndoHistory.cxx L575-578）+ `AtStart`（L170，`= !types[index-1].mayCoalesce`）——从当前动作回退到操作开始边界（组封口动作），组内全部动作一次回退。

**上轮应改-1 的双重错误确认**：
- **时序前提错误**：推演假设 NewLine 的 undo 组在 SCN_CHARADDED 时刻已关闭；实际 NotifyChar 在 `UndoGroup` 作用域内、析构之前同步发出（Editor.cxx 结构直接证伪）。
- **机制分支引用错误**：引用的 UndoHistory.cxx:283 顶层 coalesce 判定只在 `undoSequenceDepth == 0` 生效；组内动作走非顶层分支（L311-314）且 L266-269 强制 `mayCoalesce=true`，上轮把顶层分支行为套到组内动作上。

与修复子智能体（实测）、主智能体（源码核实）两方结论一致：**三方核实一致，裁决闭环**。实测行为（一次 UNDO 整体回退 + CANUNDO==0 + 二次无操作）与源码机制推演完全吻合，也与需求验收标准 7 原始字面语义一致（无需 DEC-005 方案 A 的「接受 2 步边界」）。

### [可选-1] 测试（通用）：多光标 UNDO 后未逐点断言双光标位置（选区数保持 2 但 caret 具体位置未断言）

- **证据**：`src/main.cpp:2643-2647`（`g_stDocAiUndoMulti` 断言集合：三态内容 + 三态选区数 + canUndo，无 `SCI_GETSELECTIONNCARET` 位置断言）。对照 Enter 正向侧 `g_stDocAiMulti`（L2581-2582）有 caret 6/15 位置断言；既有 B4 断言 `g_stSchUndoOnceMc`（main.cpp:3479）同样只断内容+选区数。

- **影响**：不构成需求正确性问题（验收标准 7 字面已满足且强断言）；B4 光标位置语义在 undo 侧仅有数量级守护，与项目既有断言基线一致。
- **建议**：可在 `multiUndo1` 比对处补充 `SCI_GETSELECTIONNCARET` 0/1 == 3/9（Enter 前双光标位置）断言。不修复的影响：仅 undo 侧光标位置级回归无逐点守护（内容精确回退断言可捕获大部分内容级回归），无正确性与生产稳定性风险。

## 4. 其他发现（按严重度排序，全部经复核成立）

**[可选] 需求边界语义：仅大小写变化的重命名被静默 no-op — 证据
`src/core/documentmanager.cpp:239-241`（`equivalent(url,newPath)` 为 true 即 no-op 成功）—
根因：NTFS 大小写不敏感但保留，`ReadMe.md → readme.md` 判定为同一文件 — 触发条件：用户仅改
文件名大小写 — 影响：操作返回「成功」却无任何变化且无提示，与「重命名成功」心理预期不符
（Windows 桌面用户常见诉求；VS Code 支持该场景）；同时 `LocalStorage::move` 预检对同一文件
返回 AlreadyExists，两道口径都无法达成大小写改名 — 建议：对 equivalent-no-op 但词法不等价的
情形给出轻提示（如「仅大小写不同，未改名」），或两步改名支持；本行为系实现注释明确声明的
决策（"指向同一文件——如大小写/相对写法差异 → no-op"），不构成数据风险，故列可选。**

**[可选] 组装层错误文案归因不精确 — 证据 `src/main.cpp:790-795`：`DoOpenContainingFolder`
外层 exists 预检通过后，`OpenSelectInExplorer` 返回 false 的剩余原因基本只剩
`ShellExecuteW` 启动失败（explorer 被组策略禁用等）或预检与调用间文件被删的极窄竞争，但文案
统一为「文件不在磁盘上」 — 影响：极端场景误导用户排查方向，无功能损坏 — 建议：区分两段失败
文案（不存在→「文件不在磁盘上」；启动失败→「无法打开资源管理器」）。**

**[可选] `OpenSelectInExplorer` 不校验 is_regular_file（对应阶段 6 测试报告观察项①）— 证据
`src/platform/explorer.cpp:13` 仅拦 `INVALID_FILE_ATTRIBUTES` — 触发条件：传入的路径是目录
（生产链路不可达：`openPath` 的 read 已拒绝目录、`saveAs` 产出文件；即便文件被外部替换为同名
目录，行为也只是 explorer 定位选中该目录，无破坏性）— 结论：测试报告「生产路径不可达，风险
低」判断成立，同意不强制收紧 — 建议：若后续复用该函数，可补一行
`!(attrs & FILE_ATTRIBUTE_DIRECTORY)` 使「选中该文件」语义精确（`LocalStorage::move` 的源
预检已做同等目录拒绝，口径对齐）。**

**[可选][pre-existing] `LocalStorage::supports` 认领 file:/// 形式但 read/write/move 均不剥前缀 —
证据 `src/core/localstorage.cpp:72-76`（supports 经 `parseFileUrl` 认领）vs
`readRawBytes`/`write`/`move` 直接以原始 path 调 Win32/filesystem API — 触发条件：上游传入带
`file://` 前缀的 url（生产不可达：打开/保存对话框、命令行、会话 ini 均纯路径）— 影响：未来引入
真实 URL scheme 分发时该矛盾会暴露（read 阶段 NotFound）— 处置：早于本次变更、read/write 既有
同口径，`move` 与既有行为一致，未引入新矛盾；标记 pre-existing 供后续存储扩展时统一在
storage 边界剥前缀，不在本次修复（修复属接口层重构，超出本需求范围且当前不可达）。**

**测试充分性结论**：TC-001~014 与验收标准一一对应，断言业务结果（磁盘内容、url、脏状态、
事件计数、错误 kind+中文消息）。两个可接受的缺口：① 跨卷移动（`MOVEFILE_COPY_ALLOWED` 的
copy+delete 路径）未覆盖，测试均在同目录临时目录（C:/D: 双盘环境可补，标志语义由系统保证，
列为可选增强）；② 组装层模态对话框路径无自动化——模态系统对话框不可自动驱动且受项目测试
防扰约定约束，由 TC-012/013/014 与人工验收覆盖，可接受。阶段 6 测试报告观察项②（两个 e2e
高负载偶发时序竞态）涉及代码本次零改动，维持 pre-existing 判定。

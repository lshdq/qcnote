### 回归钉有效性专项（防假绿）

- **消息号正确**：`TTM_GETTOOLCOUNT = WM_USER+13` 与 commctrl.h 一致（v4.71+ 即支持，v5/v6 均响应）；实测对 v6 tooltip 控件返回 1。
- **非恒真**：v5.82 拒绝 72 字节 `sizeof(TOOLINFOW)` → `TTM_ADDTOOL` 静默失败 → 工具数 0 → `CHECK(n == 1)` 必失败。断言成立性依赖进程绑定 v6，该前提由 test_manifest.rc 嵌入 manifest 保证（证据 XML 证实），且 Catch2 无用例跳过机制。
- **TTM_GETTEXT 用法正确**：`TOOLINFOW` 结构无 `cchTextMax` 成员（该字段属 TCITEM/LVITEM 等，非 TOOLINFO）；现代用法 `wParam=128`（缓冲 TCHAR 数）+ `ti.lpszText=buf` + `cbSize=sizeof(TOOLINFOW)` 与 MSDN TTM_GETTEXT 契约一致，测试报告亦记录初版编译失败后修正的过程。

### 构建系统（审查重点 2）

### GDI/GDI+ 绘制（审查重点 3）

- **对象释放**：paint 中 3 个 GDI 画刷均 `CreateSolidBrush→FillRect→DeleteObject` 配对（253-255、274-276、287-289）；GDI+ 全部栈对象 RAII（Pen/Brush/GraphicsPath/Graphics 析构释放，badgePen/gapPen 同）；GDI 回退路径 SelectObject 恢复 + DeleteObject(pen)（563-565）。无泄漏。
- **先填后描顺序**：New（fill fold→draw page→彩色「+」）、Open（fill back→fill flap→draw flap→draw back→开口线）、Save（fill body→fill label→draw 三路径）均符合描边覆盖公共边惯例；back 开放路径 FillPath 自动闭合已注释说明，与基线行为对照无回归。
- **禁用态彩色跳过**：paint 按 `disabled[i]` 逐按钮传 `colorful`，禁用仅灰色线稿剪影；New 禁用分支补狗耳轮廓保证剪影完整。Wrap 按钮 `disabled[3]` 恒 false，其禁用分支当前不可达（防御性代码，无害）。
- **两主题对比度**：token 取值两主题各档（深浅适配由 TC-004 数值断言 + TC-009 人工观感双层覆盖）。

### 几何一致性（审查重点 4）

- 四处一致：`buttonRects` 间隔公式（btns[2].right + Scale(6)×2 + Scale(1)）↔ 单测 `sepGap = SeparatorMargin*2 + SeparatorWidth = 13` ↔ paint 分隔线 x0（btns[2].right + Scale(6)，恰居间隔中）↔ e2e 按钮 3 中心公式（96 DPI 下 153+22=175，实测断言通过）。
- DPI 路径：实现侧全部经 `Scale()`；e2e 侧经 `ScaleLogical(GetDpiForWindow)`；单测无 attach 时 DPI 兜底 96 与断言常量匹配。高 DPI（144）抽查：Scale(1)=2、Scale(6)=9，分隔线 [9,11) 居于 20 物理px 间隔正中，几何不变式成立。

## 4. 其他发现

### [可选] 检查项：测试脚本注释算术错误 — verify-edge-hittest-e2e.ps1:295（审查范围文档第 59 行同误）

- **结论**：注释 `# x = 4 + 3*(44+2) - 2 + 6*2 + 1 + 22 = 177` 的求值结果为 **175** 而非 177（4+138−2+12+1+22=175）；第 296 行代码公式求值同为 175，与真实新几何一致（btns[3] = [153,197]，中心 153+22=175，与测试报告专项核对 3 的"中心 175"互证）。**代码行为正确、测试通过，仅注释等号后的值写错**；审查范围文档「= 177 逻辑px」同为笔误。
- **根因**：手写求和笔误（177 − 175 = 2）。
- **触发条件/放大路径**：后续维护者按注释值 177 校验或"修正"公式，会引入真实 2px 偏移；脚本坐标本已与新几何脱钩过一次（测试报告专项核对 3 记录的旧值 164 观察项），注释错误会放大下次几何变更的排查成本。
- **影响**：不改变当前运行结果；误导性文档。
- **建议**：将 295 行注释与审查范围文档的 177 更正为 175（一行注释修改，不改代码逻辑）。

### [可选] 检查项：v6 视觉样式下 tooltip 换肤消息被忽略，E5 机制静默失效 — src/ui/tooltip.cpp:13-23、src/ui/tabs.cpp:524-526

- **结论**：`TTM_SETTIPBKCOLOR`/`TTM_SETTIPTEXTCOLOR` 在视觉样式启用时被系统忽略（MSDN 明确说明该消息在 manifest 启用 visual styles 后无效果；tooltip 由主题类 "Tooltips" 绘制）。本任务加入 Common-Controls 6.0 依赖**恰恰使视觉样式生效**：改动前 v5 无视觉样式、换肤生效；改动后这两处调用变为无实际效果的死路径——深色主题下 tooltip 不再呈现 toolbarBackground 深底/textPrimary 浅字，转而跟随系统浅色 tooltip 样式。
- **根因**：DEC-001 选择 manifest 方案的固有副作用；tooltip.cpp/tabs.cpp 的换肤代码未同步注明该限制。
- **触发条件/放大路径**：深色主题下悬停任意按钮/Tab/状态栏即可观察；系统主题样式自带对比度保证，**可读性不受损**，且需求边界条款（"manifest 变更带来的主题化视觉属预期改善，不额外定制"）与 DEC-001 影响栏已覆盖此类视觉变化——不构成需求冲突。
- **影响**：E5 tooltip 换肤特性静默失效；后续维护可能误以为换肤仍生效而据此排查颜色问题。
- **建议**：在 tooltip.cpp `applyThemeColors` 与 tabs.cpp 相应处补一行注释说明「v6 视觉样式启用后本消息被系统忽略，保留调用仅为无视觉样式环境的兜底」；如团队认为深色 tooltip 主题化重要，可另立需求评估暗色 tooltip 方案，不属本任务范围。

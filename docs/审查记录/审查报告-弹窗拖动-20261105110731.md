### 深度专项核查（审查输入指定关注点）

- **userMoved 状态机 / 绑定与字面值切换**：绑定 `x: userMoved ? storedX : clampX(resolveDefaultX())`（MovableDialog.qml:52-53）由 storedX/storedY 驱动而非直接写 x/y，绑定永不中断；二次拖动 originX 取当前 storedX 连续正确；拖动中窗口 resize 时下一次 onActiveTranslationChanged 以新 clamp 收敛；拖动越过阈值前（未激活）不打断未拖动态。**结论：状态机无缺陷。**
- **DragHandler 事件与模态/焦点/键盘冲突**：DragHandler 仅在 header（弹窗内容之上、遮罩之上），不与 contentItem 的 TextField/按钮争抢；release 时 active 置 false 先于 translation 重置被 dragging 守卫拦截（drag002 拖后位置断言 ±1px 通过证实无弹回）。drag008 证明 Tab/Shift+Tab 把手（Label）不获焦、模态焦点不逃逸。**结论：无冲突。**
- **clamp 数学与退化情形（弹窗大于窗口）**：窗口约束 minimumWidth: 800 / minimumHeight: 500（Main.qml:27-28），最大弹窗宽 520 < 800，clampX 上界恒 ≥ 720、clampY 上界恒 ≥ ~447，退化情形（hi<0）当前**物理不可达**；防御性缺口见"其他发现 #1"。
- **Dialog.title 置空影响**：测试定位三文件已全部适配（MovableDialog 短名 + dialogTitle 属性；classNameMatches 包含匹配对 `MovableDialog_QMLTYPE_x`/`SearchDialog_QMLTYPE_x` 均成立）；无障碍补偿（header Label Accessible.name/StaticText）已实现，读屏实际行为见"其他发现 #2"。
- **测试合成鼠标事件可靠性**：mouseDrag 经 QTest::mouse*（QWindowSystemInterface 投递，move 携带 press 按键状态），注释明确说明 DragHandler 依赖该路径；headerGrabPoint 对"弹窗越出窗口后把手中心在窗外"做了窗口内钳制；drag003 的窗口外 move QWARN 为合成事件预期现象（测试报告已注明）。**结论：可靠。**
- **CMake 注册**：src/CMakeLists.txt 按字母序插入 qml/MovableDialog.qml，模块注册完整；独立构建通过。
- **视觉与 Material 默认 header 比对**（Qt 6.11.2 源码 Material/Dialog.qml）：字号（dialogTitleFontPixelSize）、elide、padding 24/bottom 0 完全同款；色差（AppTheme.textPrimary #212734 vs Material 默认调色板 87% 黑）与背景差异（默认 header 带 dialogColor PaddedRectangle vs 透明）视觉上不可辨/同色，见"其他发现 #3"，由 TC-011 兜底。

## 4. 其他发现（经复核成立，按严重度排序）

1. `[可选] 正确性-防御性编程: clampX/clampY 在上界 hi < 0 时返回负值` — 证据 src/qml/MovableDialog.qml:65-72（`Math.min(Math.max(v, 0), hi)`，hi<0 时结果为负） — 根因：未对上界取非负下限 — 触发条件：父项宽度 < 80px 或高度 < headerHeight（当前 minimumWidth: 800 / minimumHeight: 500 约束下物理不可达） — 影响：一旦未来放宽窗口最小尺寸或组件复用于小父项，将复现 DEC-005 注释所述"存储负值与框架钳位脱节 → 反向拖动死区"同构故障 — 建议：`const hi = Math.max(0, parent.width - keepWidth)`（clampY 同理）。不修的影响：当前不可触发，仅未来复用风险。
2. `[可选] 可访问性-读屏核验缺口: Dialog.title 置空后弹窗容器级可访问名依赖 header Label 的 Accessible.name（StaticText）补偿` — 证据 src/qml/MovableDialog.qml:116-117 — 根因：offscreen 平台无法验证真实屏幕阅读器对弹窗（Popup 语义容器）与标题的朗读行为 — 触发条件：读屏用户打开任一弹窗 — 影响：标题文本经 StaticText 进入无障碍树，读屏可获取，但容器名称朗读顺序/方式可能与原 Dialog.title 行为有差异，风险低 — 建议：在 TC-011 人工验收时补一条讲述人/NVDA 朗读弹窗标题的核验项。不修的影响：仅读屏体验的不确定性，无功能缺陷。
3. `[可选] 视觉一致性-token 取色与 Material 默认的极微差异` — 证据 src/qml/MovableDialog.qml:113（AppTheme.textPrimary #212734/#e8eaf0）vs Qt 6.11.2 Material/Dialog.qml 默认 header（无显式 color，继承调色板 ≈87% 黑；带 dialogColor PaddedRectangle 背景） — 根因：需求同时要求"沿用现有 Material 标题样式"与"颜色取 AppTheme token"，token 值与 Material 默认非逐位相同 — 触发条件：肉眼并排对比 — 影响：色差（Δ≈十几/通道）与背景差异（同色背景 vs 透明）视觉不可辨 — 建议：TC-011 人工验收时确认标题栏视觉无回退即可；无需代码改动。不修的影响：无。

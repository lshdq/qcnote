## 三、依赖、兼容性与优化机会

- **第三方依赖**：无新增/升级依赖，仅改内部实现。无冲突风险。
- **公共接口兼容**：`modified` 由可写变只读、删 `setModified`、新增 `markSaved`。经全量 grep（src + tests，QML/C++ 双侧）确认无任何外部写入方；`markSaved` 未标 `Q_INVOKABLE`，QML 无法绕过 DocumentManager 清脏，接口收紧方向正确。DocumentListModel/SessionManager 无隐藏依赖（SessionManager 仅连接 urlChanged/cursorPositionChanged/encodingChanged）。
- **性能**：`setContent` 含 3 次 QString 比较（入参判等 + wasModified + 翻转检测）。键入/删除场景长度不等 O(1) 早退；等长替换（多光标列编辑、全选替换）为 O(n) memcmp，10 MB 文档约毫秒级，且该场景本身伴随 TextArea O(n) 全文重排，字符串比较非瓶颈。与需求非功能需求声明及 DEC-002（用户澄清性能顾虑后选定）一致。**无恶化项。**
- **内存**：脏文档额外持有一份基线字符串（COW 独立 data）；干净/刚加载/刚保存状态下与 m_content 共享 data 零拷贝。量级 = 每文档一份内容大小，需求已声明，可接受。
- **并发/资源**：Document 全部生命周期在主线程（QML 单例树），无共享可变状态跨线程；无新增需释放资源。不适用。

## 五、其他发现（按严重度排序）

1. `[可选]` 信号一致性: `applyLoadedState` 存在 `modified` 瞬态不一致窗口 — 证据(document.cpp:129-135) — 根因: `m_content = content; emit contentChanged();` 先于 `m_savedContent = content` 执行，contentChanged 的同步槽内读 `modified()` 得到"新内容 vs 旧基线"的比较结果（如干净文档按编码重载出不同文本时槽内瞬时为 true，终值 false） — 触发条件: 未来任何在 contentChanged 直接连接槽/同时依赖 content 与 modified 的 QML 绑定中读取 modified 的代码（当前消费者 EditorArea onContentChanged 仅读 content/cursorPosition，无 QML 绑定同时依赖两者，**当前零实际影响**） — 影响: 无现行缺陷，属契约陷阱 — 建议: 将 `m_savedContent = content` 上移到 `emit contentChanged()` 之前（wasModified 已在函数入口取值，语义不变），消除窗口。不修复的影响: 后续新增 contentChanged 消费者可能读到瞬态错值，属难排查的隐性时序问题。

2. `[可选]` 测试可观测性: TC-010 消息接管期吞掉全部非 Binding loop 诊断 — 证据(tst_windowclose.cpp:144-150) — 根因: `bindingLoopCollector` 仅收集 Binding loop 消息，其余 qDebug/qWarning 被静默丢弃且不转发原 handler — 触发条件: TC-010 运行期间（含两个 Bench 的 QML 加载与析构）任何 Qt/QML 告警 — 影响: 该用例失败需诊断 QML 加载警告时信息已丢失 — 建议: collector 内将非目标消息转发至先前 handler（guard 已保存 restore 指针，可另存静态指针或在 collector 中按需转发）。不修复的影响: 仅降低测试失败时的可诊断性，不影响断言有效性。

均不阻塞合入。未发现 pre-existing 问题（审查路径内既有代码：EditorArea 回写防环、DocumentTabs 命令式宽度重算、saveAs 遮蔽重载顺序均经本次改动交叉验证无回归）。

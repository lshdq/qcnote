### 通用检查项结论

- **资源**：BCrypt 句柄（alg/hash）全路径释放（`textutil.cpp:114-141`）；文件句柄在 readRawBytes/write/writeFileAtomically 全失败路径 CloseHandle；SHGetKnownFolderPath→CoTaskMemFree（`sessionmanager.cpp:281-293`）；FormatMessageW→LocalFree；PCRE2 code/match_data 在 findAll/rebuild/replaceAll 全路径释放。无泄漏。
- **异常**：错误统一 `std::expected<T, StorageError/OpenError/wstring>`，无空 catch、无吞错；用户可见消息全中文宽字符。
- **整数边界**：文件大小上限 INT32_MAX（`localstorage.cpp:96-101`）；字节偏移 int 契约（<2GB）在 searchengine.h/multicursor.h 显式声明且与 2GB-1 文件上限闭合；ReadFile/WriteFile 按 1GB 分块防 DWORD 截断；sha256 分块喂入防 ULONG 截断。
- **并发**：确认无多线程设计（core 层无 thread/atomic，单线程事件驱动）；MulticastEvent emit 快照迭代，回调内退订/重入 close 安全（documentClosed 先发、unique_ptr held 至函数返回——有专门测试锁定时序）。
- **UTF-8 边界**：零长度匹配按序列步进不落多字节中间；wordRangeAt 落序列中间回退序列首；GBK 编码失败定位以代理对整体为单元。
- **安全**：正则 ReDoS 有编译期 match/heap limit；无 SQL/命令注入面；错误消息不含敏感信息。

## 五、其他发现（复核后成立，按严重度排序）

本次审查未发现阻塞级或应改级问题。以下为可选项与已知边界确认：

### 5.1 [可选] F 扩展点：storageForUrl 分发依据与头文件声明不一致

- **结论**：`storageForUrl` 按 `supports()` 分发，而 `DocumentStorage::supports()` 默认恒真且 `LocalStorage` 未重写——任何路径（含未来网络 scheme 的 path 形态）都会被先注册的 LocalStorage 吞下；`scheme()` 虚函数（LocalStorage 返回 `L"file"`）实际未参与分发。
- **证据**：`src/core/storage.h:56`（默认 `return true`）、`src/core/localstorage.h`（无 supports 重写）、`src/core/documentmanager.cpp:369-375`（遍历 supports）；对比 `storage.h:1-6` 头注释「storageForUrl 分发，未注册报『不支持的存储类型』」。
- **根因**：分发逻辑依赖上层 `parseFileUrl` 预检拦截非 file scheme，core 层 supports 兜底语义与声明脱节。
- **触发条件/放大路径**：仅在未来注册第二个存储实现时显现——后注册的存储（如网络存储）永远不可达，或需修改 LocalStorage/storageForUrl 才能接入。
- **影响**：当前版本行为正确（单存储 + 上层拦截），无功能错误；对 F「不堵死」构成接口语义误导（扩展时需改一处现有代码而非纯新增）。
- **建议**：`LocalStorage::supports()` 重写为仅认本地 path 形态（排除已知网络 scheme），或 `storageForUrl` 改用 `scheme()` 与 path 前缀匹配分发。不修复的影响：未来网络存储里程碑接入时必须触碰本文件且注释继续失真。

### 5.2 [可选] searchExpandReplacement 空 string_view 传入 append(nullptr, 0)

- **结论**：引用不存在的组时 `groupText` 返回默认构造的空 `string_view`（`data()==nullptr`），随后 `out.append(t.data(), t.size())` 传入 `(nullptr, 0)`。按标准严格读法 `[s, s+n)` 需有效范围，属技术性 UB；MSVC 实现 n=0 不解引用，无实际危害。
- **证据**：`src/core/searchengine.cpp:269-270`（`out.append(t.data(), t.size())`）、`:229-245`（groupText 三处 `return {};`）。
- **根因**：未区分「空 view」与「空但有效的 view」。
- **触发条件**：替换串引用不存在的捕获组（如 `$5` 组 5 不存在、UNSET 组）——B5 需求明确要求输出空串，属正常使用路径。
- **影响**：MSVC/当前工具链零危害；切换 sanitizer 或标准库硬化模式（如 libc++ hardening）可能触发诊断。
- **建议**：改为 `if (!t.empty()) out.append(t.data(), t.size());`。不修复的影响：工具链演进时产生非预期编译/运行期诊断噪音。

### 5.3 [可选] multicursorNextOccurrence 重叠判定最坏平方复杂度

- **结论**：`overlapsSelection` 对每个候选命中线性扫描全部选区，总复杂度 O(出现数 × 选区数)；「1MB 全同字符文档 + Ctrl+Shift+L 全选（10^6 选区）+ 再 Ctrl+D」的最坏输入可达 10^12 量级比较（分钟级卡顿）。
- **证据**：`src/core/multicursor.cpp:297-319`（`overlapsSelection` 线性扫描 + `idx = hit + 1` 逐字符推进）。
- **根因**：命中与选区重叠时仅从下一字符继续，未跳过该选区；选区列表未利用有序性。
- **触发条件/放大路径**：刻意构造的高频重复短词内容 + 全部出现已选后继续 Ctrl+D。正常笔记文档（词出现数与选区数均为小量）无感知。
- **影响**：极端输入下 Ctrl+D 长时间无响应（结果正确，仅慢）；1MB 属性能豁免线（>10MB）以内但内容形态非典型。
- **建议**：命中落入选区 `[s,e)` 内时将 `idx` 直接跳到 `e`（选区之后的命中不可能再与该选区共享字符），可降至 O(出现数)。不修复的影响：保留理论卡顿路径。

### 5.4 [可选] registerFormat 头文件注释「空指针忽略」与引用签名矛盾

- **结论**：`documentmanager.h:148` 注释宣称「空指针/重复忽略」，但签名 `registerFormat(DocumentFormat& format)` 为引用参数，不可能合法传入空指针；实际实现仅做重复忽略。`registerStorage` 同构。
- **证据**：`src/core/documentmanager.h:148` vs `src/core/documentmanager.cpp:333-338`。
- **影响**：纯文档误导（后续维护者可能误以为有空指针防御语义）。
- **建议**：删除注释中「空指针」字样。不修复的影响：注释持续失真。

### 5.5 [可选] CMakeLists 中 CATCH2_CORE_SOURCES 恒为空集（死 glob）

- **结论**：`file(GLOB CATCH2_CORE_SOURCES ".../vendor/catch2/src/*.cpp")` 无匹配（Catch2 v3 源码全在 `src/catch2/` 子目录，src 顶层仅有 CMakeLists.txt），该变量是死集合，实际源码由 RECURSE glob 收齐。
- **证据**：CMakeLists.txt Catch2 段（两条 glob）+ vendor/catch2/src 目录清单实测。
- **影响**：无构建危害（RECURSE 已覆盖 + catch_main.cpp 被 EXCLUDE）；仅误导后续维护。
- **建议**：删除 `CATCH2_CORE_SOURCES` glob 与其在 add_library 中的引用。不修复的影响：无效配置残留。

### 5.6 [可选] 原子写实现双份维护

- **结论**：`LocalStorage::write`（`localstorage.cpp:189-247`）与 `writeFileAtomically`（`inifile.cpp:513-563`）维护两份几乎相同的「GetTempFileNameW + WriteFile + FlushFileBuffers + MoveFileEx(REPLACE_EXISTING) + 失败清理」实现，语义一致（后者多父目录创建）。
- **影响**：修复一处缺陷（如未来加长路径支持、临时文件名碰撞强化）时易漏另一份。
- **建议**：LocalStorage 复用 `writeFileAtomically`（差异仅 createParentDirs=false 与错误消息，可用参数弥合）。不修复的影响：双份漂移风险。

### 5.7 已知边界确认（不计新问题，与审查范围说明一致）

- **路径大小写敏感比较**：`documentForPath`（`documentmanager.cpp:317-326`，lexically_normal 后 `==` 精确比较）与草稿去重（`draftcachemanager.cpp:256-259`，wstring 精确比较）均为形态敏感比较。Windows 大小写不敏感文件系统下，不同形态路径（如命令行手输小写 vs 对话框规范大小写）会开出双 Tab，后续保存互相覆盖且不经遮蔽重载提示。此为父流程已列明的已知边界（与旧版行为一致的既有语义），本次审查确认其存在于实现，未发现范围说明之外的新触发路径（WM_COPYDATA 转发路径的参数归一在 platform 层处理）。

**Scintilla 语义声称逐项源码核实**（实现注释的所有关键声称均与 vendored 源码一致）：

1. NewLine「全部 "\n" 插入完成后才逐个发 SCN_CHARADDED」——Editor.cxx NewLine 原注释「Perform notifications after all the changes as the application may change the selections in response to the characters」，与代码一致（多光标幂等检测的设计前提成立）。
2. SCI_INSERTTEXT wParam=插入位置、lParam=NUL 结尾串按 strlen 取长——Editor.cxx InsertText 分支一致。
3. SCI_INSERTTEXT 无条件 `SetEmptySelection` 塌缩多选区、光标按 `newCurrent > insertPos` 才自动平移——一致（Enter 后光标恰 == 插入点不平移，单光标需显式推进的判断正确）。
4. SCI_GETLINE lParam=0 返回含 EOL 的行长、写入内容不 NUL 终止——`std::string prev(len, '\0')` 尺寸精确无溢出；「含尾部 '\n'（除末行）」注释正确。
5. SCI_GETTEXTRANGEFULL cpMin/cpMax 为 inter-character 半开区间（len=cpMax-cpMin，写 len+1 字节含 NUL）——`prefix(ws.size()+1)` 尺寸精确无溢出；幂等前缀比较取前 ws.size() 字节正确。
6. SCI_SETSELECTION/ADDSELECTION wParam=caret、lParam=anchor，SETSELECTION 清附加选区——Editor.cxx 消息分支一致。
7. 幂等检测前置 `caret - lineStart >= ws.size()` 是 GETTEXTRANGE 越界的必要防御（保证 cpMax ≤ Length）——设计正确。
8. 降序插入下行号稳定性：ws 纯空白无 '\n'，插入不改行数，行号全程稳定——正确。
9. coalesce 条件（顶层同类插入、位置紧邻）——UndoHistory.cxx AppendAction 一致；空选区 Enter（"\n" at p + ws at p+1）恰好满足紧邻条件。
10. IME 提交串逐字符（AddWString → InsertCharacter → NotifyChar）——需求「IME 含 \n 同样补缩进」可达且正确。

**测试代码质量复核**：阶段 11 七个场景断言（内容+光标位置+选区数）逐条人工推演全部自洽（含 TC-007 多光标降序插入偏移的精确心算验证）；阶段机 11→12 推进不破坏既有 closeAll 顺序；g_testClipboard 单处定义无重复；ps1 TC-I08 与既有 I05/I06/I07 场景结构、变量复用模式、隔离（独立 userdir）、headless 防扰约定完全一致。

## 三、依赖、兼容性与优化机会

- **无新增第三方依赖**：全部基于现有 Scintilla 消息与 core 纯函数 ✓。
- **会话 ini 数据兼容**：`SessionData::autoIndent` 采用 `std::optional<bool>`（无键 → nullopt → 默认开）与 wordWrap/lineNumbers 同模式；parseBool 复用同款宽容实现（"true"/"1"）；写侧仅在 optional 有值时写（PersistSessionNow 恒有值恒写）。旧版本读新 ini（含 autoIndent 键）多余键自然忽略。**结论：兼容性无风险**。
- **分层依赖方向**：scintillaedit.cpp（editor 层）include core/textutil.h 方向合法；core 层无反向依赖 ✓。
- **优化机会**：applyEnterIndent 每光标 SCI_GETLINE 取整行（O(上一行字节) 而非 O(缩进)）——超长单行下每次 Enter 分配行长临时串。与既有 SCN_MODIFIED 全串 setContent O(文档长) 相比低一个量级，且需求非功能条款明示笔记级不做 >10MB 优化，**不建议改动**。

## 四、其他发现（按严重度排序）

### [应改-1] 需求实现正确性/undo 语义：单光标「选区替换后 Enter」需 2 次 Ctrl+Z，与验收标准 7 字面语义不符且相对改动前是行为回归

- **证据**：`src/editor/scintillaedit.cpp:564`（`undoGuard{sci, sels > 1}`——单光标不包 undo 事务，依赖 coalesce）。Scintilla 源码证据链：
  - `Editor.cxx` NewLine：`UndoGroup ug(pdoc, !sel.Empty() || (sel.Count() > 1))`——**非空选区时组激活**（ClearSelection 删除 + "\n" 插入同组）；
  - `UndoHistory.cxx:344-352` EndUndoAction：组结束无条件 `actions.types[PreviousAction()].mayCoalesce = false`；
  - `UndoHistory.cxx:283` AppendAction 顶层判定：`!actions.types[targetAct].mayCoalesce` → coalesce 失败 → 补缩进的 ws 插入**新起一个用户操作步骤**。
- **根因**：DEC-002 方案 A 的 coalesce 路径仅在「Enter 前空选区」（NewLine 的 UndoGroup 未激活）时成立；非空选区时 NewLine 自身的 undo 组关闭了合并通道，而 SCN_CHARADDED 时刻（NewLine 已 ClearSelection）无法回溯区分 Enter 前选区状态。
- **触发条件/放大路径**：单光标选中一段文本 → Enter（上一行有前导空白）→ Ctrl+Z 一次仅回退缩进（内容处于「选区已删+已换行」中间态，被替换文本暂不可见），第二次才回退到 Enter 前状态。改动前该场景一次 Ctrl+Z 整体回退——**开关开启引入了该常见场景的撤销步数翻倍**。
- **影响**：验收标准 7「单光标回车后一次 Ctrl+Z 整体回退」的字面语义在此常见子场景不成立；TC-010 前置条件（空选区）未覆盖该路径，测试报告未暴露。
- **建议**：SCN_CHARADDED 挂点无法将该插入并入已关闭的 NewLine 组，无零侵入修复方案（并入组需回到 DEC-001 方案 A 拦截自实现，回归风险高）。**务实处置**：(a) 由用户/主流程决策是否接受该边界——接受则更新需求文档与决策记录（DEC-002 补记此边界），并在 doc selftest 阶段 11 补「选区替换 Enter 后 undo 步数」断言固化当前行为防进一步劣化；(b) 不接受则需在多光标子类化层（已有 VK_RETURN 观察点）预记 Enter 前选区空/非空并在非空场景改用整组事务语义（此时 ws 组与 NewLine 组仍是两步，需产品权衡「2 步但可预期」vs 拦截自实现）。不处置的影响：高频编辑场景（选中替换）撤销体验劣化且无任何断言守门，后续维护者可能无意进一步改变此行为。
- **备注**：多光标场景（sels>1）已用事务包裹，undo 侧为「缩进组 → 换行组」两步、每步语义完整，符合需求「多光标补缩进合并为一步」的批准语义，无此问题。

### [应改-2] 测试（通用）：多光标 undo 撤销侧无任何断言——需求「多光标场景补缩进合并为一步」与 B4 撤销选区历史（SCI_SETUNDOSELECTIONHISTORY=1）交互未验证

- **证据**：`src/main.cpp:2571-2578`（TC-007 断言集合仅含正向 selCount/content/双光标位置，无 SCI_UNDO）；全代码库搜不到多光标 Enter+缩进后 SCI_UNDO 的断言（main.cpp 既有 SCI_UNDO 用例均为单光标/编号场景，编号场景不经过 Enter 路径）。
- **根因**：测试用例文档 TC-007 未定义 undo 后断言；DEC-002 的多光标半边（BEGIN/ENDUNDOACTION 合并为一步）只经设计推演，无回归测试。
- **触发条件/放大路径**：多光标 Enter+缩进 → Ctrl+Z 回退 ws 组——期间 SCI_INSERTTEXT 逐次塌缩选区（组内）+ 组末 SETSELECTION/ADDSELECTION 重建；undo selection history 的组边界记录（RememberSelectionOntoStack 组内跳过、组首动作压栈）与组末重建选区的 redo 记录时序均为复杂交互路径。任一环节行为漂移（Scintilla 升级、重建顺序调整）现有测试不会失败。
- **影响**：guide.md「行为变更附带一个测试，其断言在该变更回归时会失败」不满足；B4「多光标编辑单步回滚后光标集合不丢」语义在本需求引入的新动作类型上无守护。
- **建议**：在 doc selftest 阶段 11（TC-007 场景后）追加：多光标 Enter+缩进 → SCI_UNDO 一次 → 断言内容回到多光标 Enter 后状态（各行缩进移除）且选区数仍为 2、光标集合回到各行行首；SCI_UNDO 二次回到 Enter 前内容与选区。不补的影响：该需求明示语义（撤销侧）与 B4 交互在回归中静默漂移不可见。

### [可选-1] 需求文档与实际行为不符：「空行虚拟列 Enter：原生先补空格、再叠加上行前导空白」的机制描述与 Scintilla 5.6.9 实际行为（丢弃虚拟列）不符

- **证据**：`vendor\scintilla\src\Editor.cxx` NewLine：`sel.Range(r).ClearVirtualSpace()`——Enter 路径直接丢弃虚拟空间（补空格仅存在于 InsertCharacter 路径的 `RealizeVirtualSpace`）。需求文档「边界与约束」第 25 行描述为「原生先补空格、再叠加」。
- **根因**：需求撰写时对 NewLine 路径虚拟空间行为的推断有误（InsertCharacter 与 NewLine 是两条不同路径）。
- **影响**：实际行为（虚拟列丢弃 + 补上一行缩进）落在需求「接受」条款兜底范围内，不构成功能缺陷；但文档误导未来维护者。
- **建议**：更正需求文档该句为「空行虚拟列 Enter：原生丢弃虚拟列（不补空格）、新行行首叠加上一行前导空白，接受」。

# 已缓解：编辑区纯竖直拖拽选区限制

> 状态更新（2026-11-06 第 4 轮修复）：本限制已由 PointHandler 被动驱动方案消除，
> 任意方向、任意时长的拖拽均产生选区。以下保留根因记录与历史沿革供跟踪。

## 原现象（已缓解）

在编辑区按住鼠标左键，从按下时刻起 800ms 内**始终纯竖直向下拖动、横向漂移 ≤ 10px**
（约 startDragDistance）时，不产生文本选区，视图不动、无滚动。

"先横向移动超过 10px、再竖直拖动"的路径正常产生选区。

## 根因链（对照 Qt 6.11.2 源码验证）

1. `QQuickTextArea` 的 `QQuickPressHandler` 把基类 `QQuickTextEdit::mousePressEvent`（内含 `setKeepMouseGrab`）延迟到 800ms 定时器结束、或首个横向位移超过 `startDragDistance`（约 10px）的 move 事件才补放执行；且该定时器**只在横向移动时取消**（`QQuickPressHandler::mouseMoveEvent` 只检查 X 坐标）。
2. 定时器到期后补放执行时销毁了保存的 press 事件；此后 `QQuickTextControlPrivate::mouseMoveEvent` 因 `mousePressed == false` 直接返回，后续 move 不再驱动选区（这是纯竖直场景的真根因；横向先行时首个 |dx| > 10px 的 move 会先取消定时器并补放 press，`keepMouseGrab(true)` 生效，故正常）。
3. 延迟窗口内 `keepMouseGrab` 未设置时，ScrollView 内部 Flickable 的 `childMouseEventFilter` 在拖拽超过阈值、该轴可滚动时会抢夺独占鼠标抓取，转为视图拖动滚动（该路径已由 `nativeDragGuard` 守卫先行阻断）。

## 缓解方案（2026-11-06 第 4 轮修复）

`src/qml/EditorArea.qml`：

- `onPressed`（左键分支）按下即 `positionAt` 定位光标并自持锚点 `nativeDragAnchor`
  （不再依赖 Qt 补放的 delayed press——它可能被 800ms 定时器销毁而永不补放）；
- TextArea 子级新增 `PointHandler`（Qt 6 被动点跟踪，不抢独占抓取，TextArea
  抓取期间照常收点更新）：按下期间以 `select(锚点, positionAt(当前点))` 直接
  驱动选区扩展。与原生补放路径并存时锚点/终点一致、逐步收敛，无双头冲突；
  双击/三击为独立 dblclick 事件不经 onPressed（守卫不置位），原生选词/扩展不受影响。

现状：**任意方向、任意时长的拖拽均产生选区**（含 800ms 内纯竖直 ≤10px 漂移的极端场景）。

剩余平台差异说明：按住拖出编辑器视口边缘时，选区 clamp 至可见/文档边界后不再继续扩展
——Qt Quick 原生无 dragAutoScroll，这与 VS Code 等编辑器拖选自动滚动的惯例存在平台差异，
属平台能力差异而非缺陷，真机验收时不应据此误判。

## 历史沿革

- 2026-11-05 第 1~3 轮：`nativeDragGuard` 守卫（按下期间禁用内部 Flickable
  `interactive`）阻断 Flickable 抢夺路径，防御层保留。
- 2026-11-06 第 4 轮：onPressed 自持锚点 + PointHandler 被动驱动 select，
  消除 800ms 纯竖直限制（本记录转为"已缓解"）。

## 后续路径

- 本质根因仍是 Qt 上游缺陷（`QQuickPressHandler` 延迟按下定时器仅在横向位移时取消，
  到期销毁保存的 press）。升级 Qt 版本或上游修复后，可重新评估 PointHandler 驱动层
  是否可简化/移除。

## 关联修复

- `src/qml/EditorArea.qml` 的 `nativeDragGuard` 守卫（2026-11-05）：编辑器按下期间禁用 ScrollView 内部 Flickable 的 `interactive`，阻断其子事件过滤器在延迟按下窗口内抢夺鼠标抓取。
- `src/qml/EditorArea.qml` 的 `nativeDragAnchor` 锚点 + `PointHandler` 被动驱动（2026-11-06，DEC-004）。

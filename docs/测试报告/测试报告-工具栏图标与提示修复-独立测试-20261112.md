## 专项核对

### 1. 回归钉有效性（TC-001 防假绿）

- **manifest 嵌入证实**：`mt.exe -inputresource:...;#1` 分别提取两 exe 的 RT_MANIFEST，
  `qcnote.exe` 与 `test_ui.exe` 均含 `Microsoft.Windows.Common-Controls version="6.0.0.0"
  publicKeyToken="6595b64144ccf1df" processorArchitecture="*"` 依赖
  （证据存档：`docs\测试报告\证据-工具栏图标与提示修复-20261112\*.xml`）
- **断言真实性**：`TTM_GETTOOLCOUNT==1` 用例真实存在于 test_ui.cpp（源码 grep 命中，
  经真实宿主窗口 `Toolbar::attach()` 后对 tooltip hwnd 发消息断言），Catch2 无用例
  跳过机制，27 用例全数执行；按标签 `[ui][toolbar]` 单独运行 11 用例 129 断言通过
- **CMake 依赖链证实**：`tests/test_manifest.rc` 挂入 test_ui 目标 + `/MANIFEST:NO` +
  rc 源文件 `OBJECT_DEPENDS src/qcnote.manifest`（manifest 变更会触发 rc 重编，开发轮
  发现的 Ninja 缺 depfile 问题已修复）

### 2. manifest 变更影响面（comctl32 v6 生效属预期变化）

- theme selftest 像素采样四点（标题栏/工具栏/内容区/状态栏）均通过：工具栏采样点为
  窗口水平中心 × 条带垂直中点（main.cpp `SampleThemePixels`），不落在按钮/图标/分隔线
  区域，不受图标彩色化与几何右移影响
- v6 生效带来的菜单/系统控件主题化属需求声明的预期改善；本轮所有菜单/tooltip 相关
  断言（逻辑级）无一因 manifest 变更失败，无需放宽任何断言
- tooltip 显示链路（TC-001/002/006/007）在真实 v6 进程内全部按预期工作

### 3. 几何变化影响面（按钮 3 因分隔线右移 13 逻辑像素）

- **新几何**：按钮 3 = [153, 197]（逻辑 px，96 DPI），中心 175；按钮 0-2 几何不变
- `verify-edge-hittest-e2e.ps1` 第 295 行以**旧几何公式**计算按钮 3 点击点：
  `LeftMargin + 3×(44+2) + 22 = 164`——旧中心；新几何下 164 仍落在按钮 3 矩形
  [153, 197] 内，实测 TC-06 四次点击/重启恢复全部通过。**观察项（非失败）**：
  该公式已与新几何脱钩（点击点偏左 11px、非按钮中心），后续若几何再变更可能落到
  间隔区或按钮 2 上导致误报/漏测，建议开发轮将其改为按 toolbar_metrics 动态计算
  或直接取 175（本轮按「检查并报告」处理，未改动该脚本）
- `verify-doc-selftest.ps1` 的工具栏场景点的是按钮 0（新建，几何未变），通过
- 既有单测几何断言（3+1 分组）与实现一致；无其他 selftest/e2e 依赖旧按钮 3 坐标

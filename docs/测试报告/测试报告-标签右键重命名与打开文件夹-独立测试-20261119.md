### 偶发失败分析（verify-instance-shell / verify-session-draft）

- 三处失败均为时序采样特征：I10 便携草稿 0 条（防抖落盘窗口）、I05 草稿恢复少末字符、
  I06 光标采样 +1（150ms sleep 与 Ctrl+Tab 切换/防抖 tick 竞态）。
- 判定依据：① 原样重跑全部通过；② 失败路径（草稿落盘时机、编辑器切换采样）与本次
  改动（rename / explorer / 菜单模型）无代码交集——`draftcachemanager`、`sessionmanager`
  均未改动；③ 首跑发生在 5 个脚本连续执行后的高负载时段。
- 结论：非本次改动引入的稳定回归；属 e2e 脚本固有竞态余量问题，见观察项 2。

## 生产代码观察项（非阻断，交主流程决策）

1. `platform::OpenSelectInExplorer` 仅拦截 `INVALID_FILE_ATTRIBUTES`，对「存在的目录」
   路径会以 `explorer /select` 定位该目录（接口语义无 `is_regular_file` 预检）。生产路径
   不可达（文档 url 均为文件路径），风险低；如需收紧可在实现加常规文件预检。
   （本轮单测因此仅覆盖 false 分支，目录真弹窗场景不进自动化，防扰约定。）
2. e2e 脚本时序余量偏紧（150ms sleep 与防抖 1000ms/tick 200ms 竞态）：高负载连续执行
   时 `verify-instance-shell-e2e`（I10）与 `verify-session-draft-e2e`（I05/I06）偶发失败、
   单独重跑即过。属既有脚本问题，与本次需求无关；如需根治可加大采样余量或改轮询断言。

## 第 3 轮（按键过滤对称性回归修复，2026-11-05）

### 1. 缺陷摘要

- 来源：第 2 轮审查复审（实验实证）发现第 2 轮增量引入的新回归——`QQuickPressHandler`
  对**任意按键**都 emit pressed/released；第 2 轮给 `onReleased` 加了
  `if (event.button === Qt.LeftButton)` 过滤，但 `onPressed` 未加。
- 表现：右键/中键单击编辑器会置守卫 true，其 release 被左键过滤挡住不复位 → 守卫卡 true
  → Flickable interactive 持续 false → **滚轮失效**直到下次左键点击或焦点转移，违反验收
  标准 4"非按下状态下滚轮滚动正常"。

### 2. 修复内容

- `src/qml/EditorArea.qml`：`onPressed` 增加对称左键过滤
  （`if (event.button === Qt.LeftButton)` 才置守卫），并注释说明原因。
- `tests/test_editor/tst_editorintegration.cpp`：新增防回归用例
  `tcD005_nonLeftClick_guardNotStuck()`（右键、中键 press→release 后断言守卫 false、
  interactive true；再做左键对照断言按下置位、释放复位）；总注释"每步 settle"同步为与
  实际一致（tcD001/tcD002 每步 settleDrag() 10ms，tcD003 及之后 30ms）。
- 文档同步：`.localdoc/测试用例/测试用例-编辑区竖直拖拽选区修复.md`（自动化覆盖范围
  改为 tcD001~tcD005）、`.localdoc/需求文档/需求-编辑区竖直拖拽选区修复.md`
  （边界与约束补记非左键 press 亦默认 accepted=true 的接受性变化）。

### 4. 双击用例（tcD009）的 offscreen 环境研究记录（重要，供后续维护）

双击选词的合成验证在本环境经历三道门槛，均已定位并给出测试侧补偿（不改生产代码）：

1. **手工 DblClick 事件的 delivery 丢弃**：公共 `QMouseEvent` 构造的
   `MouseButtonDblClick` 事件 `isBeginEvent()==false`（实测：Press=true / Release=true /
   DblClick=false），`QQuickDeliveryAgentPrivate::deliverPointerEvent` 只对 begin 事件做
   press 分发，非 begin 非 end 事件仅投递给既有 grabber——事件被静默丢弃（事件过滤器实证：
   仅 QQuickView 收到、无任何 item 收到）。真实平台 DblClick 由系统（Windows）或
   QGuiApplication 双击检测合成，带正确状态。
2. **QPA 注入路径的设备类型门槛**：`QTest::mouseClick/mousePress`（QWindow 版）经
   `qt_handleMouseEvent` → `QWindowSystemInterface` 注入并触发 QGuiApplication 双击检测，
   能合成出送达 TextArea 的 DblClick（事件过滤器实证）；但注入事件使用
   `primaryPointingDevice`，offscreen 下其类型**非 Mouse**，而
   `QQuickTextControlPrivate::mouseDoubleClickEvent` 的选词分支门槛
   `isEventFromMouseOrTouchpad` 接受 Mouse 或 TouchPad——offscreen 默认设备两者皆非。
   归因修正：选词分支不可达的主因是 delivery 门槛（手工 DblClick 非 begin 事件只投递
   grabber），设备门槛为次因；synthMouse() + 直接 sendEvent 双补偿覆盖两者。
3. **最终补偿方案（已持久化）**：构造显式 Mouse 类型的合成设备 `synthMouse()`（
   `Bench::sendMouse` 增加 device 参数），双击序列为"第一击 press/release + 第二击 press
   （经 delivery，触发 onPressed 守卫/锚点语义）+ DblClick **直接 sendEvent 给 editor**
   （驱动 QQuickTextArea::mouseDoubleClickEvent 完整内部链路：补放 delayed press →
   QQuickTextControl 原生选词）+ release（守卫复位）"。诊断实证：同坐标同设备事件直接送
   item 选词成功（[6,10)），经 delivery 送 item 则不选词（设备 point 注册状态差异）。
4. **平台序列差异（如实记录，非产品缺陷）**：offscreen/QPA 合成序列的第二击为
   Press → DblClick（多一个物理 Press，守卫短暂置位）；Windows 真实序列第二击由系统直接
   以 DblClick 送达（无 Press，onPressed 不触发）。tcD009 断言语义按此调整（守卫复位断言
   在 release 后）。
5. 真机双击手感（选词边界、双击后拖拽按词扩展、三击选行）保留人工待验。

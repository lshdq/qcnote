## 决策列表

### DEC-001: 位置与活动状态记入会话而非草稿条目
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：未命名标签的位置与活动状态需要持久化；草稿条目（uid.json）是另一候选载体
- 可选方案：草稿条目记录标签位置/是否活动；会话 [documents] 记录未命名条目位置 uid + activeUid
- 最终选择：会话记录
- 选择理由：职责单一事实源——会话管「顺序与活动」（其本来就管文件顺序/active），草稿管「内容」；草稿只在 modified 时存在且 1 秒防抖滞后，无内容标签的位置靠草稿无从记录；会话 500ms 防抖 + aboutToQuit flush 更及时
- 影响：SessionManager 恢复期暂存 uid→位置映射，经查询接口交给 DraftCacheManager 消费

### DEC-002: 稳定插入算法（按会话绝对位置升序逐个插入）
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：恢复时序 = 先会话（文件就位）后草稿（未命名插入），需保证最终顺序等于关闭时顺序
- 可选方案：恢复完统一重排（需 model move 批量接口）；未命名条目按会话位置升序逐个 insert 到绝对位置
- 最终选择：升序稳定插入
- 选择理由：文件相对序已由会话保证，未命名按绝对位置升序插入数学上可证最终序一致；无需新增 model 批量重排接口，DocumentManager 仅需带 index 的插入
- 影响：restoreUntitledDraft 增加 insertIndex 参数（默认 -1 兼容追加）；位置越界钳制

### DEC-003: 激活优先级 activeUid 匹配 > activeBefore 复位 > firstRestored
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：活动标签可能为未命名（会话 activeBefore 是文件兜底值，非用户真实活动）
- 可选方案：仅 activeUid 匹配（无匹配不激活）；三级优先
- 最终选择：三级优先
- 选择理由：activeUid 是用户真实活动的最精确表达；无匹配时（无内容未命名标签不恢复等）依次回退到上一工作流既定规则，行为连续不跳变
- 影响：DraftCacheManager 末尾激活逻辑调整；上一工作流 DEC-002/006 规则成为兜底层级

### DEC-004: 无内容未命名标签不恢复（维持既定设计）
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：保序需求下空标签是否占位
- 可选方案：空标签也恢复（占位保完整序）；不恢复（空位自然消除）
- 最终选择：不恢复
- 选择理由：空标签无信息量，恢复徒增噪音；其余标签相对顺序不受影响；与既有「无草稿不恢复」设计连续
- 影响：activeUid 指向空标签时匹配不到 → 按 DEC-003 回退

### DEC-005: 兼容边界——旧会话格式与无会话环境
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：旧格式会话文件无 uid 键；C++ 单测环境可能无 SessionManager 实例
- 可选方案：迁移旧格式；读取时容错跳过
- 最终选择：读取容错（未命名条目无 uid 视为无效丢弃，行为回退现状）；DraftCacheManager 经 SessionManager::instance() 判空
- 选择理由：会话文件本就是「尽力恢复」语义（缺失文件静默跳过既有先例）；无迁移价值
- 影响：首启/旧格式行为与现状完全一致

### DEC-006: 无位置记录条目排序键改 max + 显式追加（审查可选 #1 采纳修复）
- 阶段：阶段 7 修复轮
- 背景：无位置记录条目的 sessionPosition=-1 与追加哨兵 -1 双重语义复用，排序实际排最前（与注释「排最后」矛盾）；在「文件缺失 + 无位置记录条目混排 + 钳制」共存的极边缘场景下相对序颠倒（数据不丢）
- 可选方案：维持现状记后续迭代；排序键改为有记录用位置、无记录用 numeric_limits<int>::max()，插入显式传 -1 追加
- 最终选择：修复（含「文件缺失+无记录条目混排」用例锁定期望语义）
- 选择理由：消除语义矛盾与误导注释，改动十余行；顺序还原是本需求核心承诺，边缘缝也应对齐
- 影响：仅无会话位置记录条目（会话丢失/旧格式场景）的处理顺序，常规场景净效果不变

### DEC-007: activeUid 匹配空串防御（审查可选 #2 采纳修复）
- 阶段：阶段 7 修复轮
- 背景：pendingActiveUid 空串（常态）与伪造无 uid 草稿条目（外部手工注入才可达）匹配成立会误激活、越过 activeBefore 复位
- 可选方案：维持（依赖写入侧 uid 恒非空事实）；匹配前加 !pendingActiveUid.isEmpty() 防御
- 最终选择：加防御（一行成本）
- 选择理由：消除对注入数据的防御缺口，成本近零
- 影响：无正常路径行为变化

### DEC-008: 文件缺失时未命名与存活文件相对序近似维持现状（审查可选 #3）
- 阶段：阶段 7 修复轮
- 背景：文件缺失被跳过后，未命名与其后存活文件的相对序可能颠倒（未命名彼此相对序不受影响）；需求边界「位置越界钳制」已声明接受
- 可选方案：会话恢复期按存活序列重编号换算位置；维持钳制近似
- 最终选择：维持现状，需求文档边界节补记说明
- 选择理由：完全精确需会话/草稿协同重排且仍无法覆盖代开时序盲区，成本高于收益；数据不丢、影响仅为观感
- 影响：需求文档边界补充；后续迭代清单 +1（如产品提出精确要求再评估）

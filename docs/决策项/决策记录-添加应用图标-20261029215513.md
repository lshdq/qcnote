## 决策列表

### DEC-001: 图标生成链采用本机 Qt Svg 自研工具
- 阶段：方案设计（阶段 2）
- 背景：需要将 SVG 母版转为多尺寸 ICO；本机无 ImageMagick、Inkscape，Python 仅为 Microsoft Store 占位符不可用
- 可选方案：① 安装 ImageMagick/Python 等外部工具；② 自研小型 Qt Svg 光栅化工具 + PowerShell 打包 ICO；③ 手工维护各尺寸位图
- 最终选择：方案②——`tools/icongen`（QSvgRenderer 光栅化）+ `tools/make-ico.ps1`（ICO 二进制拼装）
- 选择理由：零外部依赖、单一 SVG 源避免多套资产漂移、可重现生成；方案①引入环境依赖，方案③维护成本高且易不一致
- 影响：新增 tools/ 目录与独立构建步骤；主构建不受影响

### DEC-002: ICO 采用 PNG 压缩条目，六档尺寸
- 阶段：方案设计（阶段 2）
- 背景：需确定 ICO 内部条目格式与尺寸集合
- 可选方案：① PNG 压缩条目（Vista+）；② 传统 BMP 条目（XP 兼容）；③ 单一 256 尺寸靠系统缩放
- 最终选择：方案①，尺寸 16/24/32/48/64/256
- 选择理由：Qt 6 仅支持 Win10+ 无 XP 兼容需求；PNG 条目体积小；小尺寸专档比系统缩放更清晰
- 影响：无实质性风险

### DEC-003: icongen 工具不进入主构建
- 阶段：方案设计（阶段 2）
- 背景：icongen 仅在图标变更时使用，需决定其构建组织方式
- 可选方案：① 独立 CMake 工程（tools/icongen），按需构建；② 挂入主构建用 option 控制；③ 一次性临时代码
- 最终选择：方案①
- 选择理由：主构建保持精简，工具代码入库可重现；过程构建目录（build-icongen）用后即清，符合构建目录约定
- 影响：换图标时需先独立构建工具再执行生成

### DEC-004: 审查应改项与可选项一并修复

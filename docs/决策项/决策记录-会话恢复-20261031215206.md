## 决策列表

### DEC-001: 会话保存时机采用"持续防抖保存"而非"仅退出时保存"
- 阶段：方案设计（阶段 2）
- 背景：会话状态需要在退出时落盘，但崩溃/被杀进程时无退出钩子
- 可选方案：A. 仅退出时保存（实现最简，崩溃丢失全部会话）；B. 每次变化立即落盘（崩溃安全，按键级落盘开销）；C. 变化后 500ms 防抖统一落盘 + aboutToQuit 兜底 flush
- 最终选择：C
- 选择理由：崩溃最多丢最后 500ms 的光标变化、文件列表不丢；写盘频率被防抖约束，开销可忽略；退出兜底保证正常退出不丢挂起状态
- 影响：SessionManager 需要防抖定时器与 m_restoring 屏蔽标志；aboutToQuit 连接为必要路径

### DEC-002: 会话存储采用 QSettings（IniFormat）+ 编号键，而非逗号拼接列表或自定义 JSON
- 阶段：方案设计（阶段 2）
- 背景：需持久化有序文件列表到用户目录配置文件
- 可选方案：A. QSettings 字符串列表（逗号分隔，文件名含逗号时有解析歧义）；B. QSettings 编号键（`1\url`、`1\cursor`、size 计数）；C. 自定义 JSON 文件（灵活但需手写解析与容错）
- 最终选择：B
- 选择理由：文件名含逗号（Windows 合法）在 A 下有解析风险；C 引入不必要的解析代码与损坏处理面；B 结构清晰且 QSettings 原生支持转义与容错
- 影响：读取侧需按 size 循环取键，坏条目逐个丢弃不影响其余

### DEC-003: 光标持久化锚点放在 Document（C++ 属性），而非 QML 侧持久化
- 阶段：方案设计（阶段 2）
- 背景：光标状态当前仅存在于 QML TextArea 中，C++ SessionManager 无法读取
- 可选方案：A. Document 增加 cursorPosition 属性，QML 双向同步（同值无信号防环）；B. QML 侧自行收集光标并传入 SessionManager（收集点分散、时序脆弱）
- 最终选择：A
- 选择理由：单一数据源，SessionManager 与 EditorArea 都只与 Document 交互；值相等不发射信号天然消除回写环；applyLoadedState 不动该属性，保持"另存覆盖重载不动光标"语义
- 影响：Document 新增公开属性；EditorArea delegate 增加双向同步与 ensureCursorVisible

### DEC-004: 窗口 normal 几何由 QML 侧仅在 Windowed 状态记录，而非 C++ 读 QWindow::normalGeometry
- 阶段：方案设计（阶段 2）
- 背景：最大化时 x/y/width/height 报告最大化几何，需另行获取 normal 几何
- 可选方案：A. QML 监听几何变化且仅在 visibility===Windowed 时记录 + visibilityChanged 记 maximized 标志；B. SessionManager 从 topLevelWindows 取 QWindow::normalGeometry（C++ 侧集中，但与窗口对象耦合、单例时序复杂）
- 最终选择：A
- 选择理由：无需 C++ 查找窗口实例，避免与 QML 窗口创建时序耦合；几何校验仍收敛在 C++ 纯函数中可测
- 影响：Main.qml 增加几何上报逻辑；校验逻辑在 SessionManager 内独立成纯函数

### DEC-006: 会话恢复预检增加"无可用存储的条目静默跳过"
- 阶段：执行开发（阶段 5，T2 实现决策）
- 背景：损坏条目（无 scheme 的相对 URL）QUrl 解析仍视为有效，直接交给 openUrls 会发 openFailed 导致启动弹错
- 可选方案：A. 仅做本地文件存在性预检（损坏条目仍会触发 openFailed 弹窗）；B. 预检同时校验 storageForUrl 可用性（坏条目与未来非本地 scheme 均静默跳过）
- 最终选择：B
- 选择理由：需求要求"坏条目丢弃、不阻断启动"，A 不满足；B 使恢复路径零弹错
- 影响：恢复对无存储支持的 URL 静默跳过；正常打开（用户主动）路径不受影响，仍弹错

### DEC-007: SessionManager 构造时预读 [window] 节置窗口缓存有效标志
- 阶段：执行开发（阶段 5，T2 实现决策）
- 背景：启动时序为 restoreDocuments（末尾 saveNow）先于 QML 读取几何；若新实例窗口标志恒为无效，首次 saveNow 会 remove("window")，抹掉上次退出保存的几何
- 可选方案：A. 构造时预读 [window] 缓存到成员（windowState 从缓存校验返回）；B. saveNow 在窗口标志无效时保留旧 [window] 节不删（读取与写入路径分离，状态来源两处）
- 最终选择：A
- 选择理由：单一状态来源（成员缓存），saveNow 逻辑无需特判；windowState 返回校验后的缓存值，避免防抖未落盘时读到陈旧文件
- 影响：windowState() 语义为"构造以来最近一次已知窗口状态"；QML 侧上报后缓存即时更新

### DEC-009: SessionManager::m_manager 改为 QPointer 持有
- 阶段：执行开发（阶段 5，段错误修复）
- 背景：集成测试暴露多引擎时序下 DocumentManager 可先于 SessionManager 析构，裸指针悬空（SIGSEGV）
- 可选方案：A. 仅修测试时序（生产单引擎不触发，隐患留存）；B. m_manager 改 QPointer + 既有判空安全降级（双修）
- 最终选择：B
- 选择理由：任何"管理器先死"时序（未来多窗口/多引擎、测试）都安全跳过而非崩溃；QPointer 零成本（判空逻辑已存在）
- 影响：悬空后 restoreDocuments/saveNow 静默跳过；生产单引擎路径行为不变

### DEC-010: 光标滚动改手动实现（scrollCursorIntoView），弃用 ensureCursorVisible
- 阶段：执行开发（阶段 5，光标回写失效修复）
- 背景：TextArea 的 ensureCursorVisible 为 Qt 私有 PIMPL 方法，QML 调用必抛 TypeError；且异常中断下行同步处理器导致 selfCursorSync 标志卡死、用户光标永不回写（生产缺陷）
- 可选方案：A. 移除调用不滚动（光标恢复但可能不可见）；B. 按 cursorRectangle 手动调整 ScrollView contentY + try/finally 保证标志复位
- 最终选择：B
- 选择理由：需求要求"光标停在上次编辑处"，可见性是体验的一部分；finally 保证未来任何异常不再中断回写链路
- 影响：EditorArea 新增 scrollCursorIntoView；恢复路径滚动到位，用户交互路径仍走 Qt 原生滚动

### DEC-012: 窗口几何恢复采用"数据源先行"更新（审查 P0-1 修复）
- 阶段：执行开发（阶段 5，第二轮审查修复）
- 背景：窗口未显示时 visibility 为 Hidden，恢复几何赋值触发的 onXChanged 走不进 Windowed 分支；visible=true 同步发 visibilityChanged → syncWindowState() 以初始默认值 (0,0,1000,640) 覆盖会话，几何持久化往返断裂（审查黑盒两轮实证）
- 可选方案：A. onXChanged 去掉 Windowed 条件（会把最大化几何误记为 normal 几何）；B. Component.onCompleted 应用几何前先同步更新 lastNormal\*（数据源先行）
- 最终选择：B
- 选择理由：保留"仅 Windowed 记 normal 几何"的既有不变量；一处更新消除覆盖窗口。配套 lastMaximized 属性仅在 Maximized/Windowed 转换时维护（Minimized 保持），顺带修复最小化期间 maximized 被写 false（P2-1）
- 影响：恢复后不动窗口的默认路径不再丢失几何；tc014 经缺陷注入反向验证可拦截该回归

### DEC-013: 滚动载体改用 ScrollView.contentItem，保留自定义滚动与精确断言（审查 P1-1 修复）
- 阶段：执行开发（阶段 5，第二轮审查修复）
- 背景：ScrollView 无 flickable 实例属性（TextArea.flickable 是附加属性），scrollCursorIntoView 恒早退为死代码；反向验证另发现 Qt 6 的 TextArea 置于 ScrollView 会自动 attach 并原生 ensureCursorVisible（含程序化光标赋值），用户可见影响已被原生行为缓解
- 可选方案：A. 删除自定义滚动函数（依赖 Qt 原生 attach 行为，横向覆盖与未来行为变化无保障）；B. 改用 contentItem 获取内部 Flickable（实证可用）并补横向滚动，测试同时断言端到端效果与自定义实现（重置 contentY 后直调函数）
- 最终选择：B
- 选择理由：不依赖 Qt 内部 attach 实现细节；显式横向滚动覆盖 NoWrap 长行；精确断言使函数回归（如属性名再写错）可被拦截
- 影响：恢复路径滚动按设计生效；与原生滚动幂等共存

### DEC-015: 恢复预检排除目录（isFile 对齐存储读取语义）
- 阶段：执行开发（阶段 5，第三轮审查修复；扩展 DEC-006 语义）
- 背景：会话 URL 指向的路径被替换为同名目录时，`QFile::exists` 预检通过但 LocalStorage::read 失败 → openFailed 启动弹错，违背"恢复路径零弹错"意图
- 可选方案：A. 维持现状（目录属 DEC-006 文字外灰色地带）；B. 预检改 `QFileInfo::isFile()`（存在且是常规文件），目录条目按坏条目静默跳过
- 最终选择：B
- 选择理由：与 LocalStorage::read 的失败语义对齐，恢复路径保持零弹错；一行改动无行为放宽
- 影响：目录条目不再尝试打开；用户主动打开目录路径的弹错行为不变

### DEC-014: SessionManager::create 经 DocumentManager::create() 确保管理器单例存在（审查 P2-2 修复）
- 阶段：执行开发（阶段 5，第二轮审查修复）
- 背景：create() 原依赖"Main.qml title 绑定先创建 DocumentManager"的隐式时序，重构后可能永久绑定空管理器且静默失效。DEC-008 弃用方案 B 的理由是"SessionManager::create 内调用 DocumentManager::create(nullptr,nullptr) 借用工厂副作用、语义含糊"——指传空引擎参数的借用写法
- 可选方案：A. instance() 为空时 qWarning 降级；B. 把本工厂收到的 qmlEngine/jsEngine 正路传给 DocumentManager::create(qmlEngine, jsEngine)（幂等：已有实例复用、空时创建登记）
- 最终选择：B
- 选择理由：消除 QML 侧引用顺序的隐式依赖（时序自保证），优于事后告警；与 DEC-008 不冲突（此处为工厂正规调用，非传空参数借用）
- 影响：SessionManager 不再可能绑定空管理器；文档头注释同步更新

### DEC-011: 光标回写分支增加防环标志（修复同源选区回归）
- 阶段：执行开发（阶段 5，回归修复；修复子智能体在方案外发现并经隔离验证后补充）
- 背景：doc 信号下行处理器对 editor.cursorPosition 同值赋值时，MoveAnchor 语义仍重置锚点、清空用户选区，导致 test_editor tc105/tc112 回归
- 可选方案：A. 下行赋值前判同值跳过（依赖值比较，语义脆弱）；B. 回写分支置 selfCursorSync（try/finally 复位），与 selfContentSync 防环模式对称
- 最终选择：B
- 选择理由：与文件内既有防环模式一致；经"还原→复现→补充修复→通过"完整隔离验证
- 影响：用户光标回写期间的下行同值赋值被整体抑制，选区保持

### DEC-008: 新增 DocumentManager::instance() 访问器，供 SessionManager 单例获取既有实例
- 阶段：方案设计（阶段 2）
- 背景：SessionManager 单例工厂需要拿到 DocumentManager 单例；s_instance 为私有静态成员
- 可选方案：A. 新增 static instance() 返回 s_instance；B. SessionManager::create 内调用 DocumentManager::create(nullptr,nullptr)（借用工厂副作用，语义含糊）
- 最终选择：A
- 选择理由：显式表达"取既有单例"语义，C++ 测试与 QML 工厂两处受益；实现一行、无破坏性
- 影响：DocumentManager 公开接口新增一个静态访问器

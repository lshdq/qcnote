## 决策列表

### DEC-001: 检测机制采用轮询而非目录通知（ReadDirectoryChangesW）
- 阶段：方案设计（阶段 2）
- 背景：需要在单线程 Win32 消息循环架构下感知磁盘文件变化
- 可选方案：A) WM_TIMER 轮询 stat+hash；B) ReadDirectoryChangesW 后台线程通知；C) 仅窗口激活时检测
- 最终选择：A（轮询，默认 1000ms）
- 选择理由：与现有单线程事件驱动架构一致，无线程安全与生命周期复杂度；单活动文档 stat 开销可忽略；辅以切换标签/窗口激活立即检测降低延迟感知
- 影响：检测粒度为轮询间隔；新增 timer id 7（1–6 已占用）

### DEC-002: stat 初筛 + 内容哈希确认的两级校验
- 阶段：方案设计（阶段 2）
- 背景：mtime 变化不等于内容变化（touch/属性修改），仅凭 stat 会误报
- 可选方案：A) stat+size 变化即判定修改；B) 每轮全量读文件比哈希；C) stat 初筛 + 变化时才读内容比哈希
- 最终选择：C
- 选择理由：正常会话零额外 IO；复用既有 `Document::baselineHash()`（SHA-256）；消除 touch 误报
- 影响：stat 变化但内容相同时需更新快照防止每轮重读

### DEC-003: 自动重载编码走自动识别而非强制当前编码
- 阶段：方案设计（阶段 2）
- 背景：文件已被第三方程序重写，原编码假设可能失效
- 可选方案：A) 强制 `doc->encoding()`；B) 自动识别（BOM → 严格 UTF-8 → GBK）
- 最终选择：B
- 选择理由：与 openPath 默认识别语义一致；识别错误可经既有「按编码重载」菜单纠正
- 影响：重载后编码/换行/BOM 元数据随 `applyLoadedState` 刷新

### DEC-004: 「保留」抑制按 uid + stat 版本记录
- 阶段：方案设计（阶段 2）
- 背景：用户选「保留」后若每轮 poll 重复弹框会打断工作
- 可选方案：A) 保留后永久忽略该文件后续变化；B) 按已决策 stat 版本抑制，文件再变重新决策
- 最终选择：B
- 选择理由：与 Notepad++ 语义一致；外部再次修改（新版本）重新进入决策更安全
- 影响：monitor 需记录每文档已决策 stat 版本

### DEC-005: 基线快照刷新点选择
- 阶段：方案设计（阶段 2）
- 背景：自身保存/另存/重命名/重载都会改变 stat，必须防自触发；且快照需覆盖多种基线重建路径
- 可选方案：A) 显式在每条路径调用 refreshBaseline；B) poll 时对无快照/url 不符的文档自动重建 + 保存路径（modifiedChanged→false / metadataChanged）订阅刷新
- 最终选择：B（自动重建 + 事件订阅），关键写路径辅以显式刷新
- 选择理由：openPath（干净→干净无事件）、saveAs/rename（url 变）、save（modified→false）各有事件或特征，自动重建兜底防止遗漏新路径
- 影响：快照以 uid 为键，url 记录在快照内用于失配检测

### DEC-006: 检测器边界语义（查询失败传播 / 注入缺省 / 删除对决策记录的影响 / 缺失采样归一）
- 阶段：开发（阶段 5，子任务 A：core 层检测器）
- 背景：已批准方案定义了主判定管线，但若干边界路径（refreshBaseline 查询失败、注入为空、删除后决策记录、缺失文件的 mtime/size 取值）未显式约定，实现时须一次定死并可供 main.cpp 接线子任务直接依赖
- 可选方案：A) 各边界按最接近的主管线就近延展、不显式记录；B) 显式约定防御语义，并入实现注释与单测钉住
- 最终选择：B
- 选择理由：边界行为可预期、可测（尤其查询失败的 nullopt 传播——曾因直接解引用空 optional 产生 UB，单测非确定失败），接线子任务无需二次裁量
- 影响：
  - refreshBaseline：查询失败（nullopt）保持原快照不变（下轮 poll 按既有快照比对自愈）；url 为空（未命名）等价 forget；
  - 注入缺省：stat 注入为 null → 全部按查询失败处理（poll 惰性无动作、不建快照）；内容注入为 null → stat 变化时按「内容与基线一致」降级（静默推进快照，不产出 Modified，宁漏报不误报）；
  - stat 采样归一化：exists=false 时 mtime/size 一律按 0 存储/比较（缺失态收敛为单值，防查询方垃圾值制造「不存在的两个版本」）；
  - 确认不存在时清除已决策 stat 版本（文件消亡则旧版本决策失效，删除重建后的同 stat 版本视为新事件，不沿用「保留」抑制）。

### DEC-007: DocumentManager 新增 reloadFromDisk（与 reloadWithEncoding 共享内部机制）
- 阶段：开发（阶段 5，子任务 B：main.cpp 接线）
- 背景：干净文档自动重载 / 脏文档三选框「重新加载」需要按自动识别编码（DEC-003）重载；既有 reloadWithEncoding 强制传入 TextEncoding，无法直接表达「自动识别」
- 可选方案：A) 直接复用 reloadWithEncoding 并传文档当前编码（违背 DEC-003——文件已被第三方重写，原编码假设可能失效）；B) 接线层自行 openPath+applyLoadedState 组装（绕过管理器事件/钳制管线，重复实现且易漏）；C) DocumentManager 新增 reloadFromDisk，与 reloadWithEncoding 共享私有 reloadInternal（forced = nullopt 即自动识别）
- 最终选择：C
- 选择理由：存储层 read(path, nullopt) 本就表达自动识别链（BOM → 严格 UTF-8 → GBK，与 openPath 默认语义一致）；共享实现保证换行重探测/光标钳制/不置脏/事件传播（applyLoadedState 链）与按编码重载完全一致，无重复代码
- 影响：documentmanager.h/.cpp 新增公开 API reloadFromDisk + 私有 reloadInternal；reloadWithEncoding 语义/错误消息不变（既有单测零改动全过）

### DEC-008: 干净文档自动重载失败的静默降级
- 阶段：开发（阶段 5，子任务 B：main.cpp 接线）
- 背景：timer tick 内自动重载（reloadFromDisk）可能失败（文件正被第三方写入的中间态、被独占锁定等低频边界）；此时无用户交互上下文，弹框会打断输入
- 可选方案：A) 弹错误框（打断用户，且下一轮 tick 可能重试再次弹框）；B) 静默跳过本轮（快照已推进到新 stat，同版本不重试，下次 stat 变化重新走管线）+ OutputDebugStringW 诊断
- 最终选择：B
- 选择理由：快照推进语义使失败自限（同 stat 版本不重复尝试，绝不弹框风暴）；文件写完（stat 再变）后自动恢复；错误现场经 OutputDebugStringW 留痕可诊断。对照：脏文档三选框选「重新加载」失败仍弹错误框（用户显式动作的失败须显式反馈）
- 影响：PollActiveDocumentNow 的干净分支失败路径无任何 UI；相关 ContentQuery 读失败按「内容不符」方向返回 false（误报走用户决策，比静默吸收外部修改安全）

### DEC-009: stat 采样三分的 MSVC 实测修正（not_found 同时置 ec）
- 阶段：开发（阶段 5，子任务 B：main.cpp 接线）
- 背景：生产 StatQuery 用 std::filesystem::status(path, ec) 三分；首版实现「ec 非零 → nullopt」先于 not_found 判定，自测 TC-105 删除场景实测不弹删除提示
- 根因（最小复现实测）：MSVC STL 对不存在的文件，status 返回 file_type::not_found **且** 同步置 ec（ERROR_FILE_NOT_FOUND/ERROR_PATH_NOT_FOUND）——「确认不存在」被误判为「查询失败」，poll 每轮跳过，永不产出 Deleted
- 可选方案：A) 先查 ec 再查 type（错误——即首版缺陷）；B) 先判 type==not_found → 确认不存在；其余 ec 错误（type 多为 none：权限/网络）→ nullopt；存在但非常规文件（目录）→ 按不存在
- 最终选择：B
- 选择理由：三分语义与检测器契约（DEC-006：exists=false 是真实删除、nullopt 是查询失败）对齐；TC-105 修复后删除提示/恢复/保存重建全链路通过
- 影响：StatFileForWatch 判定顺序固定为 type → ec → regular；注释钉住 MSVC 实测行为供后续维护

### DEC-010: metadataChanged 基线刷新按 url 变化触发（uid 记录上次 url 比对）
- 阶段：开发（阶段 5，子任务 B：main.cpp 接线）
- 背景：已批准方案选「OnDocumentMetadataChanged 内无条件 refreshBaseline（一次 stat 代价可忽略）」；但 metadata 事件在光标每次移动（SCN_UPDATEUI 链）时高频触发——无条件刷新会在打字期间逐键把快照重置为「当前磁盘 stat」，外部改动恰在键入间隙落盘时被静默吸收（检测器此后按新 stat 比对，永不产出 Modified），与需求防覆盖目标冲突
- 可选方案：A) 无条件刷新（批准方案原文的简化实现，存在上述吸收窗口）；B) 按 uid 记录上次刷新的 url，url 变化（另存为/重命名/外部重载换名）才刷新——正是方案原文声明的意图「url 变化 → 刷新」
- 最终选择：B
- 选择理由：实现意图（url 变化刷新）而非简化近似；开销仅一次 map 查找（远小于一次 stat）；modifiedChanged→false（保存/另存为/重载清脏）路径仍无条件刷新，写路径防自触发不受影响；poll 的快照 url 失配自动重建继续兜底未覆盖路径
- 影响：main.cpp 新增 g_fileWatchLastUrl（uid → 上次刷新 url，documentClosed 时清理）；打字期间零快照重置，外部改动最多 1 个轮询间隔内被检出

### DEC-011: filewatch 自测阶段推进机制（生产 poll tick 计数 + 对话框键盘自动应答 + TC-104 等价路径）
- 阶段：开发（阶段 5，子任务 B：selftest 模式）
- 背景：--selftest-filewatch 需要在「磁盘改动」与「断言」之间保证确定轮数的生产检测发生；posted 消息优先于 WM_TIMER 生成，改动后立刻投递阶段消息会跳过 poll；三选框「另存为…」按钮（Enter 恒触发默认按钮，键盘不可达）且生产路径弹系统文件对话框（不可自动化）
- 可选方案：A) 阶段间 Sleep 等待（时序脆弱、拖慢脚本）；B) 阶段等待计数挂 timer 7 tick——每 tick 先跑 PollActiveDocumentNow（完整生产管线）后计数，到 0 投递下一阶段消息；对话框经 g_dialogHost.onOpened 注入键盘（Enter=默认按钮=重新加载/确定，Esc=escId=保留修改——真实模态路径）；TC-104 按既有等价约定直调 acknowledge + g_docManager.saveAs + markSaved（与生产 choice-3 分支组合的同一组函数，注入目标路径绕过系统对话框）
- 最终选择：B
- 选择理由：等待轮数与生产 poll 严格绑定（确定性 + 覆盖真实管线）；模态期间不消耗等待轮数（UiLocked 同门防重入）；与 --selftest-doc 的 saveAs 阶段（直调 manager 等价路径）同约定；未期望对话框兜底自动应答防悬挂
- 影响：RunFileWatchSelftestStage 阶段机（WM_APP+12，14 阶段覆盖 TC-101..108）+ FileWatchSelftestTick（WM_TIMER 分支内调用）+ 全程 onOpened 采样对话框计数；`--watch-interval-ms=50` 由 verify-filewatch-selftest.ps1 注入；filewatch 模式加入 SelftestModeActive（屏蔽会话/草稿持久化与单实例/shell 提示），timer 7 仍启动（`!SelftestModeActive() || g_selftestFileWatch`）

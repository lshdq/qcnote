## 决策列表

### DEC-001: 等比例收缩按"可收缩量"分配而非"等量减宽"或"等比缩放宽度"
- 阶段：方案设计（阶段 2）
- 背景：空间不足时需要把缺口分配到各 Tab，且不低于最小宽度 100px
- 可选方案：a) 各 Tab 等量减宽（每 Tab 减 D/N）；b) 按宽度等比缩放
  （w_i = n_i × k，需迭代夹取下限）；c) 按可收缩量等比分配
  （w_i = n_i − D/C × (n_i − 100)，解析式一次算出）
- 最终选择：方案 c
- 选择理由：解析式无迭代收敛问题；天然保证 w_i ≥ 100（收缩量按
  (n_i − 100) 加权，短名 Tab 少收缩、长名 Tab 多收缩，与用户"各标签按
  比例缩小"意图一致）；等量减宽会使短名 Tab 先触底、长名 Tab 仍省略，
  视觉不平衡
- 影响：DocumentTabs 宽度分布计算的实现形态；行为上短名 Tab 尽量保持完整

### DEC-002: 文字测量用共享 TextMetrics + QML 依赖追踪绑定，不在 C++ 侧计算
- 阶段：方案设计（阶段 2）
- 背景：需按 displayName 实测文字宽度并随重命名/开关文档/modified 变化重算
- 可选方案：a) C++ Document 暴露文本宽度属性；b) 每 delegate 内嵌
  TextMetrics 并向根节点注册；c) 根节点共享 TextMetrics，在绑定数组中
  显式依赖 documentsModel.count + 各 doc.displayName + doc.modified
- 最终选择：方案 c
- 选择理由：不动 C++（改动范围限定单 QML 文件）；根节点集中计算天然获得
  全局视野（分配需要 Σn_i 与 W）；QML 绑定依赖追踪穿过 JS 函数调用，
  显式依赖 count 即可绕过 Q_INVOKABLE at() 无依赖问题（沿用本文件
  activeIndex 的既有"双依赖"技巧）
- 影响：DocumentTabs 内新增共享 TextMetrics 与 naturalWidths/distributedWidths
  绑定属性；无 C++ 变更

### DEC-003: 装饰尺寸常量单点定义，宽度计算与 delegate 布局共用
- 阶段：方案设计（阶段 2）
- 背景：自然宽度 = 文字宽 + 装饰宽（边距/● 标记/关闭按钮/间距），
  与 delegate 布局锚点使用同一组数值
- 可选方案：a) 宽度计算中硬编码魔法数字；b) 根节点定义命名常量，
  布局锚点与计算共用
- 最终选择：方案 b
- 选择理由：避免两处数值漂移导致"宽度算准了但布局对不上"；
  维护时只改一处
- 影响：delegate 内既有内联数字（8/5/10/2/20/4 等）改为引用常量

### DEC-004: 收缩结果向下取整，防止舍入虚增触发滚动条闪烁
- 阶段：方案设计（阶段 2）
- 背景：等比收缩产生小数宽度；若四舍五入，Σw_i 可能比可用宽度大零点
  几像素，导致 contentWidth > width 误判溢出、滚动条反复出现消失
- 可选方案：a) 直接使用小数宽度（QML 支持非整数宽度，但取整边界不可控）；
  b) 四舍五入；c) 收缩后的宽度统一向下取整
- 最终选择：方案 c
- 选择理由：向下取整保证 Σw_i + gaps ≤ W 恒成立，收缩态绝不误入滚动态；
  像素级损失无视觉影响
- 影响：distributedWidths 计算中对收缩分支 Math.floor

### DEC-005: 单 Tab 上限取 max(100, floor(W/4)) 保底
- 阶段：方案设计（阶段 2）
- 背景：用户要求上限为 Tab 区可用宽度 1/4；窗口极窄（W < 400）时
  W/4 < 100，上限将小于最小宽度，产生矛盾
- 可选方案：a) 上限直接取 floor(W/4)（极窄时上限 < 下限，规则自相矛盾）；
  b) 上限取 max(100, floor(W/4))（极窄时上限退化为下限）
- 最终选择：方案 b
- 选择理由：保证上限 ≥ 下限恒成立，极窄场景行为退化为"全部 100 + 滚动"，
  与收缩饱和路径自然衔接，无特判分支
- 影响：cap 计算式；极窄窗口无异常 Tab 宽度

### DEC-006: naturalWidths 改为命令式重算 + Repeater 信号桥（修正 DEC-002 实现形态）
- 阶段：执行开发（阶段 5）
- 背景：DEC-002 原定"绑定依赖追踪计算 naturalWidths"。开发子智能体实测：
  绑定求值过程中写共享 TextMetrics.text 会同步触发 advanceWidthChanged，
  被 Qt 判定为绑定重入，每次重算刷一批 "Binding loop detected" 警告，
  违反"无绑定循环警告"验收标准
- 可选方案：a) 每 Tab 独立 TextMetrics（避开共享写入，但对象数量随文档增长，
  且仍需向根节点注册自然宽度，结构更碎）；b) 保留绑定式并接受警告（违反验收）；
  c) 命令式 recomputeNaturalWidths() 集中计算 + 显式信号转发
  （Connections.onCountChanged 处理行增删 + 全量实例化 0 尺寸 Repeater
  逐文档转发 displayNameChanged/modifiedChanged + Component.onCompleted
  兜底初始快照）
- 最终选择：方案 c
- 选择理由：DEC-002 核心要点（共享 TextMetrics、根节点集中计算、无 C++ 改动、
  单文件）全部保留；实测零绑定循环警告；displayName/modified 无聚合信号且
  ListView 只实例化可视行，Repeater 桥是全量转发的最小实现
- 影响：naturalWidths 为普通 var 属性（命令式写入）；新增 0 尺寸 Repeater
  信号桥；行为与原方案一致（一帧内同步重算）

### DEC-007: 本文件启用 pragma ComponentBehavior: Bound
- 阶段：执行开发（阶段 5）
- 背景：Repeater 信号桥 delegate 需要访问根节点作用域；项目其他 QML 文件
  无该 pragma 先例
- 可选方案：a) 不加 pragma，沿用非限定名解析（隐式作用域，qmllint 既有
  unqualified 警告持续存在）；b) 文件头加 pragma ComponentBehavior: Bound，
  强制限定访问（delegate 内一律用 docRelay.document/root 限定）
- 最终选择：方案 b
- 选择理由：Qt 6 推荐做法，编译期作用域显式化；净减 6 条既有 unqualified
  警告；仅影响本文件编译期解析，运行时行为不变
- 影响：DocumentTabs.qml 文件头新增 pragma；后续本文件新增代码须遵守限定访问

### DEC-008: 首轮审查 3 个可选项均"暂不采纳"
- 阶段：代码审查修复轮（阶段 7 → 阶段 5）
- 背景：首轮审查 0 阻塞 / 1 应改 / 3 可选；应改项（标签字号 13 双点硬编码）
  已修复（labelPixelSize 常量化，task-fast 修复 + scoped 复测 + scoped 复审
  均通过）；3 个可选项需要处置决策
- 可选方案：
  a) 充足分支同样 Math.floor——统一"显示宽度恒整数"语义，绝对封死
     Σ+gaps 与 W 差 <1ulp 的理论浮点分叉；
  b) 补运行期字体变更重算入口（labelMetrics.advanceWidthChanged 订阅，
     需防重入）；
  c) 将算法 oracle 探针沉淀为持久回归测试（需引入 qmltestrunner 设施或
     提取算法为可导入模块）
- 最终选择：三者均暂不采纳（仅记录，不实施）
- 选择理由：a) 审查自评"不修无实际风险"——充足分支进入前提即
   Σn+gaps ≤ W，不存在舍入虚增误判路径，复审确认维持不采纳无新风险；
   b) 桌面应用无运行期改默认字体入口，且 TextMetrics 与 Text 同源字体，
   极端场景下测量与渲染同步偏移而非分裂；c) 属引入新测试框架/设施，
   超出本需求范围，复审确认不影响生产代码正确性
- 影响：无行为影响；三项作为后续迭代候选（若未来支持运行时字体切换或
  建立 Qt Quick Test 设施，回溯本决策）

## 决策列表

### DEC-001: 流程文档位置沿用 docs/ 而非 .localdoc/
- 阶段：阶段 3（生成文档）
- 背景：dev-workflow 默认在项目根 `.localdoc/` 生成需求/测试/决策/审查文档，但 qcnote 项目已有入库的 `docs/需求文档`、`docs/测试用例`、`docs/决策项`、`docs/审查记录` 目录及 12 份历史需求文档
- 可选方案：A. 按 skill 默认放 `.localdoc/`；B. 沿用项目既有 `docs/` 结构
- 最终选择：B（沿用 `docs/`）
- 选择理由：项目级目录惯例更具体，历史文档全部在 `docs/`，保持一致性便于检索与入库
- 影响：需求文档、测试用例、决策记录、审查范围文件均位于 `docs/` 对应子目录

### DEC-002: 模态对话框顶部对齐而非居中
- 阶段：阶段 2（方案设计，已随方案获批）
- 背景：用户选择模态对话框形态；居中模态会遮挡编辑区，与"全部匹配覆盖层高亮可见"的需求冲突
- 可选方案：A. 默认居中；B. 顶部对齐（编辑区上方）；C. 非模态浮出面板
- 最终选择：B
- 选择理由：保留用户选择的模态形态，同时保证背后的匹配高亮可见；C 与用户已选项矛盾
- 影响：`SearchDialog.qml` 用 anchors 顶部对齐，不用 `anchors.centerIn`

### DEC-003: 「区分大小写」默认关闭
- 阶段：阶段 3（需求细化）
- 背景：三开关的默认值未在方案中确定
- 可选方案：A. 默认开启（与多光标 Ctrl+D 的大小写敏感一致）；B. 默认关闭（Windows 记事本/VS Code 惯例）
- 最终选择：B
- 选择理由：查找场景的主流默认值是不区分大小写（记事本、VS Code、Notepad++ 均如此）；Ctrl+D 是"选中相同词"语义，与查找不同
- 影响：打开对话框时默认忽略大小写，用户可手动开启

### DEC-004: 匹配数上限 10000 的防护语义
- 阶段：阶段 2（方案设计，已随方案获批）
- 背景：超大文档 + 宽泛模式可能产生海量匹配，全部高亮与计数会卡顿
- 可选方案：A. 不设上限；B. 超限后停止计算并显示「>10000」，全部高亮停止绘制，导航/替换仍可用
- 最终选择：B（阈值 10000）
- 选择理由：防止万级以上矩形绘制卡顿；导航仍基于已计算的匹配工作
- 影响：`findAll` 计算与高亮绘制在 10000 处截断；计数显示溢出标志

### DEC-005: 零长度匹配跳过
- 阶段：阶段 2（方案设计，已随方案获批）
- 背景：`a*` 等模式在任意位置零长度命中，计入会导致高亮无意义与导航/替换死循环
- 可选方案：A. 计入零长度匹配（区间 [p,p)）；B. 全部跳过
- 最终选择：B（与 VS Code 行为一致）
- 影响：匹配列表中不存在零长度区间；仅产零长度命中的模式视为无匹配

### DEC-006: 替换串捕获组引用语法（$n 与 \n 等价、$$ 字面化）
- 阶段：阶段 3（需求细化）
- 背景：方案仅确定支持 `$1` 引用，具体语法细节未定
- 可选方案：A. 仅 `$n`；B. 仅 `\n`（Qt QString::replace 语法）；C. 双语法等价支持
- 最终选择：C（`$1`..`$99` 与 `\1`..`\9` 等价；`$$` 输出字面 `$`；引用不存在的组输出空串）
- 选择理由：同时覆盖 JS/VS Code 习惯（$n）与 Qt 惯例（\n），自实现展开解析保证两种模式行为一致可单测
- 影响：替换串展开由引擎自实现解析器承担，规则在需求文档明示

### DEC-007: 当前匹配呈现方式 = 原生选区 + 高亮层描边
- 阶段：阶段 2（方案设计，已随方案获批）
- 背景：需要在全部匹配中区分"当前匹配"
- 可选方案：A. 仅加深底色（纯颜色区分）；B. 原生选区 + 高亮层描边矩形（形状线索）
- 最终选择：B
- 选择理由：项目规约要求状态表达不得仅依赖颜色；原生选区同时免费获得选区语义与可见性滚动
- 影响：跳转时控制器写 TextArea 选区；高亮层为当前匹配额外绘制边框

### DEC-008: 查找功能与多光标互斥
- 阶段：阶段 2（方案设计，已随方案获批）
- 背景：对话框打开期间模态锁定，多光标编辑无法触发；打开瞬间的既有激活状态需要定义归宿
- 可选方案：A. 保留多光标状态，关闭对话框后恢复；B. 打开对话框即退出多光标
- 最终选择：B
- 选择理由：模态期间多光标无法交互，保留隐藏状态徒增复杂度；替换操作改写文档后多光标区间也必然失效
- 影响：打开对话框时调用 `mc.reset()`；对话框关闭后回单光标

### DEC-009: 关闭对话框保留匹配状态、F3 跳转不恢复全部高亮
- 阶段：阶段 5（集成设计）
- 背景：需求要求关闭对话框「清除全部匹配高亮」，同时 F3 在对话框关闭后可继续跳转；`SearchController::reset()` 会清空匹配状态，若关闭即 reset 则 F3 失效，若不清状态则高亮残留——两者需同时满足
- 可选方案：A. 关闭即 reset（F3 失效，违背需求）；B. 关闭仅隐藏高亮层（active=false），控制器匹配状态保留，文档内容变化时自然重算；F3 跳转以原生选区+滚动呈现，不恢复全部高亮；reset 仅用于文档关闭
- 最终选择：B
- 选择理由：同时满足「关闭清除高亮」与「F3 沿用上次参数」两条需求；匹配状态随内容变化自动失效，无泄漏风险
- 影响：SearchDialog 关闭时置高亮层 active=false、不清控制器匹配；F3 经 EditorArea 调用控制器 findNext/findPrev

### DEC-010: 外部内容重置（两阶段 contentsChange）后当前索引归「无当前匹配」态
- 阶段：阶段 6（测试结果处理）
- 背景：独立测试观察项 S-1——文档外部重置经两阶段 contentsChange 后 currentIndex 归 -1（计数显示「共 N 个」未跳转态），与引擎等效单阶段测试假设的「钳到末位下标」不同；功能无害
- 可选方案：A. 改控制器为钳制到末位合法下标（凭空制造"当前匹配"选区）；B. 保持归 -1，定义为正式语义
- 最终选择：B
- 选择理由：外部内容重置后"当前匹配位置"概念已失效，归无当前匹配态最诚实；下次 findNext 从首个匹配开始，交互无损；引擎 clampedIndex 的单阶段钳制语义（非 -1 钳到合法范围、-1 保持）不变，两阶段归 -1 是其自然结果
- 影响：无需改生产代码；tc103 真实链路断言已按此行为通过

### DEC-012: 接受清单外修复——SearchDialog 内补 F3/Shift+F3 键转发（打开态真实生效）
- 阶段：阶段 7（修复轮复核）
- 背景：O9c 测试编写时发现 Main.qml F3 Shortcut 的「对话框打开时转发」分支为死分支——模态 Popup 打开期间窗口级 QML Shortcut 不被键事件激活（探针证据：打开态 F3 后 currentIndex 恒 0）；即 ST3 声称的语义从未真实工作
- 可选方案：A. 接受修复子智能体在 SearchDialog.qml 内补的 Keys.onPressed F3/Shift+F3 转发（最小改动，未动 Main.qml）；B. 回退修复并删除 Main.qml 死分支与注释声明（打开态不支持 F3）
- 最终选择：A
- 选择理由：Main.qml 注释已声明该语义、tc201c 测试锚定该行为、对话框打开态 F3 跳转符合编辑器惯例（VS Code 同款）；B 会留下「注释说支持但实际不支持」的失真声明并缩减功能
- 影响：SearchDialog.qml 增加 Keys.onPressed 转发（清单外但最小）；Main.qml 死分支保留（关闭态 F3 主路径，其打开态分支代码现在由对话框内转发替代语义，后续可清理）；tc201c 锚定

### DEC-013: F3 转发补全 footer 焦点路径 + 修饰键过滤
- 阶段：阶段 7（复审修复轮）
- 背景：复审发现 DEC-012 修复的 Keys 转发挂在 contentItem 上，而 footer 的 DialogButtonBox 不在 contentItem 子树，键事件沿 activeFocusItem 父链传播不经过它——点击任一 footer 按钮后 F3 仍失效（DEC-012 所修缺陷在此焦点态复现）；且转发未过滤修饰键（Ctrl+F3 也触发，与关闭态窗口级 Shortcut 精确序列匹配不对称）
- 可选方案：A. footer DialogButtonBox 上补挂同款 Keys 转发 + 修饰键过滤（排除 Ctrl/Alt/Meta、容忍 KeypadModifier/NumLock、保留 Shift 分支）+ 补 footer 焦点态断言；B. 降级留档（评估发生率低）
- 最终选择：A
- 选择理由：应改项按流程必须修复；修饰键过滤与注释清理同处一段代码，边际成本≈0 且消除两态行为不对称；不修复则「注释声称支持但焦点在按钮上失效」的失真持续存在
- 影响：SearchDialog.qml footer 补 Keys 转发、转发统一过滤修饰键；tst_searchuiintegration.cpp 补 footer 焦点断言 + 清理重复注释

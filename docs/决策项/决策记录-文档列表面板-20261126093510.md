## 决策列表

### DEC-001: 面板技术形态——纯 Win32 自绘组件 vs 公共控件
- 阶段：方案设计（阶段 2）
- 背景：Notepad++ 原版用 TreeView/ListView 公共控件；qcnote 全部 UI（Tab
  条/工具栏/状态栏/欢迎页）为纯自绘组件。
- 可选方案：A. SysListView32/SysTreeView32 公共控件子窗口；B. 纯 GDI 自绘
  组件（main.cpp 鼠标路由模式）。
- 最终选择：B 纯自绘。
- 选择理由：与既有组件渲染/主题/DPI/测试缝约定完全一致（CurrentPalette
  动态取色、逻辑 token+Scale、无子窗口焦点问题）；公共控件深色滚动条与
  主题一致性需额外视觉样式 hack。
- 影响：滚动条需自绘（少量新代码）；交互消息路由集中在 main.cpp。

### DEC-002: 宽度持久化单位——物理像素 vs 逻辑像素
- 阶段：方案设计（阶段 2）
- 背景：会话既有的窗口几何存物理像素；面板宽度需跨 DPI 稳定。
- 可选方案：A. 物理像素；B. 逻辑像素（96 DPI 基准）。
- 最终选择：B 逻辑像素。
- 选择理由：同屏重启语义等价（同 DPI 换算恒等）；跨 DPI 显示器迁移时
  按比例缩放不越界；恢复时钳制兜底。
- 影响：sessionmanager 读写侧固定按逻辑值解释；自测断言用 96 基准值。

### DEC-003: 右键菜单——独立构建 vs 复用 Tab 命令集
- 阶段：方案设计（阶段 2）
- 背景：列表条目与 Tab 条目语义同构（index + 关闭/重命名/文件夹命令）。
- 可选方案：A. 新建 BuildDocListContextMenu；B. 复用 BuildTabContextMenu

### DEC-004: 开发子任务拆分与委派顺序
- 阶段：任务分解（阶段 4）
- 背景：功能跨 core/ui/main 三层，需按复杂度路由委派且控制集成风险。
- 可选方案：A. 单个 task-deep 一体完成全部开发；B. 拆为
  A(core 持久化, task-standard) ∥ B(ui 组件+单测, task-deep) →
  C(main 组装+selftest+脚本, task-deep) 三段委派。
- 最终选择：B 分段委派。
- 选择理由：A 与 B 无依赖可并行缩短周期；C 依赖前两者产出，prompt 可给
  出精确接口契约；符合 dev-workflow「每个开发子任务独立分级委派」要求。
- 影响：需在 C 的 prompt 中固化 A/B 的对外接口签名，避免集成歧义。

### DEC-007: docListVisible 解析口径——严格字面量 vs QVariant 宽容
- 阶段：执行开发（阶段 5，任务 A）
- 背景：[editor] 既有 wordWrap 的 bool 解析沿用 Qt QVariant::toBool 宽容语义
  （"1"→true、垃圾串→false）；新键 docListVisible 的非法值回退策略需定。
- 可选方案：A. 沿用 wordWrap 宽容口径（"1"/"0" 也认）；B. 仅认字面
  true/false（asciiIEquals 大小写不敏感），其余 → nullopt。
- 最终选择：B 严格字面量。
- 选择理由：写侧只产 true/false，"1" 只可能来自手改坏值；坏值回退默认
  （隐藏）优于误判 true 意外显示面板；与文件内 parseBool/parseEncodingKey
  的字面量风格一致。
- 影响：与 wordWrap 口径存在已知差异（实现注释与测试双向锁定）；如需统一
  仅改 parseSession 一处。附带决策：docListWidth 超 int 值域按非法丢弃
  （截断会 wrap 出负值违反非负语义），域内值的上限钳制归 UI 恢复层
  （任务 C 必须实现，否则 TC-005 越界钳制不闭环）。

### DEC-008: hitInteractive 语义——面板整体 vs 仅交互子区域
- 阶段：执行开发（阶段 5，任务 B）
- 背景：契约字面为「条目/滚动条/分隔条」三区域；但面板空白处点击若穿透
  到编辑器会误触文本（面板是内容区内的实体表面）。
- 可选方案：A. 仅三子区域（空白穿透）；B. 整个面板本体矩形。
- 最终选择：B 面板整体。
- 选择理由：与工具栏/状态栏「自判路由、不穿透」模式一致；空白点击语义
  = 点在面板上，不应作用于其后内容。
- 影响：组装层把面板区域整体路由给组件（含空白）；穿透语义无歧义。

### DEC-009: 宽度回调与拖拽回退语义细化
- 阶段：执行开发（阶段 5，任务 B）
- 背景：onWidthChanged 触发时机、setVisible(false) 拖拽收尾、滚动条滑块
  拖拽中断的事务性需明确（契约未覆盖）。
- 可选方案：A. up 提交仅宽度有变才回调、setVisible 隐藏时回退宽度、
  滑块拖拽中断回滚滚动；B. up 无条件发最终宽（持久化时机统一）、
  setVisible(false) 终止拖拽不回宽不回调（面板宽度语义保留现值）、
  滑块拖拽中断保留当前滚动（滚动已实时生效非事务）。
- 最终选择：B。
- 选择理由：main 以 up 的最终回调为唯一持久化时机（无变不发会漏存）；
  隐藏面板后重新显示应回到记忆宽度而非静默改宽；滑块回滚会抖动且无数据
  风险。另：未布局时 setWidthLogical 仅钳下限（maxWidthLogical_==0 视为
  无上界）——允许恢复会话宽度 260 不被首次布局前误钳到 120。
- 影响：任务 C 按此接线（up 回调即 TriggerSessionSave；恢复先 set 宽度后
  首次 layout 自然施加上界）；滚动条箭头/轨道无按住自动重复（timer id 受
  限，记后续可选增强）。

### DEC-010: selftest 参数长前缀先判定
- 阶段：执行开发（阶段 5，任务 C）
- 背景：`--selftest-doc`（wcsstr 子串匹配、首个命中生效）会抢占
  `--selftest-doclist=...`，实测误跑 doc 模式——既有解析缺陷被新前缀暴露。
- 可选方案：A. 改为精确/最长匹配重构解析器；B. 数组内把长前缀
  `--selftest-doclist` 排到 `--selftest-doc` 之前并注释固化约定。
- 最终选择：B。
- 选择理由：最小改动、零既有语义影响；重构解析器超出本任务范围且需
  回归全部既有 selftest 前缀。
- 影响：新增 selftest 前缀须遵守「长前缀先判定」约定（注释已固化）。

### DEC-011: Esc 取消拖拽经消息循环拦截
- 阶段：执行开发（阶段 5，任务 C）
- 背景：焦点在编辑器（常态）时 Esc 直达 Scintilla，主窗口 WM_KEYDOWN
  收不到，面板拖拽的 Esc 取消失效；Tab 拖拽已有同款问题并以消息循环裸
  Esc 拦截解决（main.cpp 既有决策）。
- 可选方案：A. 仅 WM_KEYDOWN 路由（焦点常态下失效）；B. 消息循环 Esc
  拦截扩展判定 g_docList.draggingSplitter()。
- 最终选择：B。
- 选择理由：与 Tab 拖拽 Esc 拦截同手法，覆盖常态焦点路径。
- 影响：Esc 拦截多一个判定分支；非拖拽态 Esc 行为不变。

### DEC-013: 面板滚轮路由接受焦点限制
- 阶段：执行开发（阶段 5，任务 C）
- 背景：WM_MOUSEWHEEL 投递给焦点窗口；编辑器持焦点（常态）时光标悬停
  面板滚轮直达 Scintilla，面板不滚动——与 Tab 条溢出滚动现状一致。
- 可选方案：A. 按光标位置重路由滚轮（全局钩子/消息层改造）；B. 接受
  限制：面板滚轮在主窗口持焦点（欢迎页态/无文档）时生效，常态经滚动条
  交互，重路由记后续增强。
- 最终选择：B。
- 选择理由：A 超出本次范围且影响编辑器滚轮语义（回归风险）；既有 Tab
  条同款限制先例，滚动条常驻可视、可用性可接受。
- 影响：需求「滚轮垂直滚动」在该焦点组合下不触发（已知限制，交付披露）；
  后续增强候选：光标位置滚轮重路由。

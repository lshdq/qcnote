### DEC-006: C++ 标准落地形态——`/std:c++latest` 替代不存在的 `/std:c++23`
- 阶段：阶段 5（M0 执行开发）
- 背景：方案锁定 C++23；实测本机 cl 19.51（VS Build Tools 2026 18.9.2）无 `/std:c++23` 开关（仅 c++14/17/20/latest），该开关被 D9002 静默忽略并回落默认 C++14
- 可选方案：A. `/std:c++latest`（实测 `_MSVC_LANG=202400`，C++26 草案模式，完整涵盖 C++23 特性：std::expected/std::print/std::flat_map 均可用）；B. 降级 `/std:c++20`（放弃 C++23 选型）；C. 等待/更换工具链版本
- 最终选择：A
- 选择理由：达成 C++23 选型意图的唯一可行路径；Scintilla 保持 `/std:c++20` 混编无 ODR 问题（边界仅 extern "C"）；风险为 C++26 草案相对 C++23 的行为差异（新增弃用告警等），升级工具链时需关注漂移
- 影响：根 CMakeLists 应用与测试 TU 用 `/std:c++latest`；代码中避免使用 C++26 独有特性，保持 C++23 可移植性

### DEC-008: 无边框方案——保留 WS_OVERLAPPEDWINDOW + WM_NCCALCSIZE 客户区计算（非纯自绘边框）

- 背景：方案 6.2 列出「WM_NCCALCSIZE 客户区扩展或纯自绘边框」两个候选；纯自绘边框需自己实现 DWM 阴影/贴靠/边框动画，代价高
- 可选方案：A. 保留完整 WS_OVERLAPPEDWINDOW，仅 WM_NCCALCSIZE 把客户区扩展到整窗（系统继续提供缩放边框/DWM 阴影/Aero Snap/Snap Layouts/Alt+Space）；B. WS_POPUP 纯自绘边框

### DEC-010: 文档内容内存表示用 UTF-8 std::string（换行 LF），不用 UTF-16
- 阶段：阶段 5（M2 委派前主流程架构决策）
- 背景：旧版 QString(UTF-16)；Win32 版需与 Scintilla、磁盘编码、会话/草稿 JSON 三方交互，需统一内容编码单元
- 可选方案：A. UTF-8 std::string；B. UTF-16 std::wstring（Win32 API 天然）
- 最终选择：A
- 选择理由：Scintilla SC_CP_UTF8 模式下 SCI_SETTEXT/GETTEXT 零转换直通（编辑器即内容宿主，Document 存元数据+基线哈希，内容可从 Scintilla 拉取）；磁盘 UTF-8 读写零转换；GBK 仅在读/写边界经 UTF-16 一次性中转（MultiByteToWideChar CP936 ↔ CP_UTF8）；会话/草稿 JSON 序列化零转换；std::string/std::string_view/std::expected 生态优
- 影响：字符计数（状态栏）经 Scintilla SCI_COUNTCHARS 或 UTF-8 工具函数；GBK U+FFFD 替换在解码边界天然发生；uid 生成改 CoCreateGuid（替代 QUuid）

### DEC-012: 正则引擎采用 vendored PCRE2（非 std::regex、非 Scintilla 内建正则）
- 阶段：阶段 5（M3 委派前主流程决策）
- 背景：需求 B5 锁定「正则表达式（PCRE 语义，`.` 不匹配换行、`^`/`$` 仅全文首尾、`(?m)` 内联控制）」；旧版 QRegularExpression 即 PCRE
- 可选方案：A. vendored PCRE2（GitHub pcre2project/pcre2）；B. std::regex（ECMAScript 方言：不支持内联 (?m)、\d/\w 语义差异、性能差）；C. Scintilla SCI_SEARCHINTARGET 的 SCFIND_REGEXP（POSIX 风格子集，不支持 (?m)/现代语法）
- 最终选择：A
- 选择理由：功能语义与需求/旧版严格对齐；静态编译无运行时依赖；BSD 许可 permissive；B/C 语义不符会造成功能回归
- 影响：vendor/pcre2 静态库（UTF 模式、JIT 按需）；替换展开仍用自实现解析器（$1..$99/\1..\9/$$，M3-A 移植）

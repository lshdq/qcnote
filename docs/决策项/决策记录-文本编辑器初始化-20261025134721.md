## 决策列表

### DEC-001: 标题栏采用 Frameless 自绘方案
- 阶段：方案设计（阶段 2）
- 背景：desktop-ui-design skill 默认布局要求顶部窗口栏为"菜单按钮 + 文档 Tab + 窗口控制按钮"
- 可选方案：A) Frameless 自绘标题栏，完整实现 skill 布局；B) 原生标题栏，Tab 放第二栏
- 最终选择：方案 A
- 选择理由：完整符合已确认的 desktop-ui-design 布局；Qt 提供 `startSystemMove/startSystemResize` 可保留系统级移动、缩放、贴靠行为，风险可控
- 影响：需自实现边缘缩放、双击最大化、窗口按钮；Win11 悬停最大化按钮的 Snap Layouts 弹出不支持（设计例外）

### DEC-002: 换行符归一化策略
- 阶段：方案设计（阶段 2）
- 背景：QML TextArea 以 LF 处理换行；Windows 文件多为 CRLF
- 可选方案：A) 加载时 CRLF/CR 归一化为 LF，记录原风格，保存时写回；B) 内容中保留原始 CRLF
- 最终选择：方案 A
- 选择理由：编辑体验一致、避免 TextArea 渲染异常；保存不破坏文件原风格
- 影响：Document 需记录 lineEnding 属性；新建文档默认 LF

### DEC-003: 编码策略 MVP 仅 UTF-8
- 阶段：方案设计（阶段 2）
- 背景：目标用户中文环境存在 GBK 文件；Qt 6 移除了 Qt5Compat 之外的编码支持
- 可选方案：A) MVP 仅 UTF-8（读容忍 BOM）；B) 引入编码探测（uchardet/Qt5Compat）
- 最终选择：方案 A
- 选择理由：控制 MVP 范围与依赖（需求已确认无第三方依赖）；编码探测列入后续演进
- 影响：GBK 文件打开可能乱码（非本期缺陷）；后续增加编码选择/探测时扩展 storage 读取接口

### DEC-004: 扩展点采用抽象接口 + 注册分发
- 阶段：方案设计（阶段 2）
- 背景：需求要求后续支持 markdown/json 格式与网络存储
- 可选方案：A) MVP 即引入 DocumentFormat/DocumentStorage 抽象接口与注册机制；B) MVP 直接写死纯文本+本地逻辑，后期重构再抽象
- 最终选择：方案 A
- 选择理由：接口成本远低于后期重构；单元测试可锁定分发行为
- 影响：核心代码略增抽象层；新格式/新存储各自新增一对 .h/.cpp 即可接入

### DEC-005: 测试策略为 C++ 单测 + GUI 手工冒烟
- 阶段：方案设计（阶段 2）
- 背景：QML UI 自动化（qmltestrunner）对 Frameless 自绘窗口与文件对话框覆盖有限
- 可选方案：A) C++ 核心单测 + GUI 手工冒烟；B) 引入 qmltestrunner UI 自动化
- 最终选择：方案 A
- 选择理由：MVP 阶段核心风险在 C++ 逻辑与系统集成行为；UI 自动化投入产出比低
- 影响：UI 回归依赖手工用例；后续 UI 复杂化后再评估引入 UI 自动化

## 决策列表

### DEC-001: 「下一个/上一个」复用 searchJumpGlobal（对话框关闭态语义）
- 阶段：方案设计
- 背景：菜单触发时查找对话框必为关闭（模态阻断菜单交互），但存在两条现成路径：`searchJumpGlobal`（关闭态，沿用控制器保留的匹配状态）与 `searchDialog.doFindNext`（对话框内语义）。
- 可选方案：A. 直接调 `searchJumpGlobal(true/false)`；B. 复刻 F3 Shortcut 的双分支（对话框可见时转发对话框、否则走关闭态）。
- 最终选择：A
- 选择理由：模态对话框打开期间主菜单不可达，方案 B 的对话框分支恒不可达；`searchJumpGlobal` 已含 `uiLocked()` / 无活动文档 / 无查找串或无匹配三重守卫。
- 影响：菜单跳转与 F3 关闭态语义天然一致（不恢复全部高亮，DEC-009），零新增逻辑。

### DEC-002: 「搜索」四项 enabled 仅绑定活动文档存在
- 阶段：方案设计
- 背景：「下一个/上一个」在无查找串/无匹配时无实际作用，可做更精细的置灰。
- 可选方案：A. enabled 仅绑 `DocumentManager.activeDocument !== null`（触发无操作）；B. 由 Main 把 `searchController.matchCount > 0` 等细粒度状态以属性传入 TitleBar。
- 最终选择：A
- 选择理由：与 F3 快捷键「无匹配无操作」语义一致（VS Code / 记事本同惯例）；方案 B 需把 EditorArea 内部控制器状态跨组件暴露给 TitleBar，增加耦合，收益有限。
- 影响：无匹配时点击菜单项无反馈（与按 F3 相同）。

### DEC-003: KeyMenuItem 内联组件提升至 TitleBar 根作用域
- 阶段：方案设计
- 背景：文件操作条目移入「文件」子菜单、「搜索」子菜单新建条目后，仍需 KeyMenuItem 显示右对齐快捷键文本；该组件原声明在 mainMenu 对象内部。
- 可选方案：A. 提升到 TitleBar 根 Rectangle 作用域，全文件复用；B. 在各子菜单内重复声明。
- 最终选择：A
- 选择理由：单一来源，避免重复声明导致样式漂移；仅声明位置变化，渲染行为不变。
- 影响：TitleBar.qml 内一处声明位置调整。

### DEC-004: 注释/文档级修复轮采用比例化收敛复审
- 阶段：阶段 7 结果处理
- 背景：审查唯一应改项为 README.md 旧菜单标题残留（用户可见文档与 UI 不符），连同同类可选项 Toolbar.qml 注释共 2 处纯文字修改；无任何行为面变化，审查报告明示"修复后无需重审代码或重跑全量测试"。
- 可选方案：A. 完整重跑独立测试（task-standard）+ 完整独立审查（task-standard）；B. 修复后由主智能体本地跑全量 ctest 确认，再以 task-fast 做仅覆盖本轮增量 diff 的收敛复审。
- 最终选择：B
- 选择理由：被测行为面与已通过测试/审查的制品完全一致（差异仅 README 一行与 QML 注释两处文字，ctest 9/9 复跑全绿）；方案 A 对两行注释重复全量流程，成本收益严重失衡。
- 影响：收敛证据链 = 本轮修复 diff + ctest 9/9 + task-fast 增量复审通过；后续若有任何行为面修复轮，恢复完整阶段 5/6/7 循环。

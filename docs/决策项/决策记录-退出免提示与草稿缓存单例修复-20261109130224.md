### DEC-001: 单例修复采用「去掉构造默认参数」而非运行时合并实例
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：Qt 6.11 `qqmlprivate.h singletonConstructionMode()` 对单例的构造选择顺序为「默认构造 > create 工厂」；DocumentManager 的 `explicit DocumentManager(QObject *parent = nullptr)` 属默认可构造，引擎直接 new 出独立实例，与工厂链实例分裂（界面用 A、DraftCacheManager 连 B）
- 可选方案：① 去掉构造默认参数（`explicit DocumentManager(QObject *parent);`）使引擎回落到 create 工厂；② 接受双实例，DraftCacheManager 惰性重取 instance()/信号转发；③ 私有化构造
- 最终选择：①
- 选择理由：编译期根治（is_default_constructible=false ⇒ 必走工厂），与 SessionManager/DraftCacheManager（无默认构造，一直走工厂）的构造语义统一；②运行时补丁复杂且顺序敏感（现状 SessionManager「碰巧正常」即是顺序运气）；③私有构造与 QML 注册模板的可达性存在风险
- 影响：create() 内部与测试栈构造调用点需机械适配（new DocumentManager(nullptr)）；构造自登记 s_instance 行为保留（幂等无害）

### DEC-002: 恢复激活规则——仅「无活动文档」时激活首个恢复文档
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：restoreUntitledDraft 不激活 + 会话无文档时 activeDocument 为空 → 恢复的未命名标签存在但内容区显示欢迎页/空白，用户感知「未恢复」
- 可选方案：恢复后总是激活最后恢复的文档；仅当 activeBefore 为空且本次有恢复文档时激活首个恢复文档
- 最终选择：后者
- 选择理由：会话已有活动标签时保持既有「不抢占」语义（上轮 TC-015）；仅空场景补激活，行为可预期
- 影响：TC-003/TC-004 分别锁定两种场景

### DEC-003: 失焦即写挂 applicationStateChanged(ApplicationInactive)
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：用户实测路径「输入 → 切任务管理器 → 强杀」中，切窗口即失焦，是防抖窗口外天然的落盘时机
- 可选方案：缩短防抖间隔；失焦即写；两者都做
- 最终选择：失焦即写（flushPending），防抖间隔维持 1000ms
- 选择理由：不增加常规编辑 IO；精准覆盖强杀前的高概率路径；C++ 单测（QCoreApplication）无该信号，判空防御即可
- 影响：强杀丢失窗口压缩为「失焦前 1 秒」

### DEC-004: 退出免提示的实现边界——保留标签页关闭三选确认
- 阶段：阶段 1（用户澄清确认）+ 阶段 2
- 背景：用户明确「仅应用退出」免提示；热退出语义（未保存内容经草稿下次恢复）已确认
- 可选方案：退出与关标签都免提示；仅退出免提示
- 最终选择：仅退出免提示；onClosing 去掉 hasUnsavedChanges 拦截，清理 continueExit/exiting/closeFlowIsExit 退出死路径；标签关闭流程原样保留
- 选择理由：用户指定；关闭标签是明确放弃意图的入口，保留确认与「不保存清草稿」语义
- 影响：tst_windowclose 退出分支用例语义反转（弹确认 → 直接退出+草稿保留），属需求变更的测试更新

### DEC-005: 补齐 QML 集成级回归测试（此前盲区）
- 阶段：阶段 2（方案设计，获批方案组成部分）
- 背景：上一轮 27 个草稿单测全绿却漏掉此缺陷——C++ 单测直接 new DocumentManager/DraftCacheManager，绕过 QML 单例解析路径；冒烟场景 A/C 断言文件系统轮换（在僵尸实例域内自洽），未断言 QML 界面状态，属假阳性
- 可选方案：仅修生产代码；生产代码修复 + 新增「真实 Main.qml + 真实防抖到期 → 断言落盘/恢复激活」的 QML 集成回归
- 最终选择：后者
- 选择理由：防止同类「QML 解析路径与 C++ 直构路径行为分裂」缺陷再次逃逸；该测试在修复前红、修复后绿，是根因的直接回归锁
- 影响：新增 QML 集成测试用例（TC-001/002/003 等）

### DEC-006: 冲突恢复路径补激活（审查可选 #1 采纳修复）
- 阶段：阶段 7 修复轮
- 背景：resolveConflicts(true) 重建未命名文档（文件缺失条目）后若 activeDocument 为空，内容区停留欢迎页——与 DEC-002 所修复症状同源，仅场景更小众（会话无文档 + 条目全冲突 + 用户选恢复）
- 可选方案：维持现状记入后续迭代；与 restoreDrafts 空场景规则对齐（无活动文档时激活首个恢复文档）
- 最终选择：对齐修复
- 选择理由：同一产品语义不应因恢复路径不同而分叉；改动数行 + 单测锁定，成本低于行为不一致的长期成本
- 影响：resolveConflicts(true) 末尾补激活逻辑；新增/扩展单测

### DEC-007: 多未命名草稿激活语义记入后续迭代（审查可选 #2 维持现状）
- 阶段：阶段 7 修复轮
- 背景：多条未命名草稿同时恢复时，激活的是处理序首个（uid 文件名字典序），非用户最后编辑者（savedAt 最新）
- 可选方案：未命名条目按 savedAt 排序并激活最新；维持「首个恢复文档」规则
- 最终选择：维持现状，记入后续迭代（需产品确认期望语义）
- 选择理由：DEC-002 已明选「首个恢复文档」且未命名条目不参与排序是记录在案的产品决策边界；改为「最后编辑现场」是语义升级而非缺陷，应随产品意图决策
- 影响：后续迭代清单 +1

### DEC-008: e2e 脚本恢复断言轮询化（审查可选 #3 采纳修复）
- 阶段：阶段 7 修复轮
- 背景：verify-hotexit-draft-e2e.ps1 恢复断言前固定 Sleep 4 秒，高负载/慢盘机器可能偶发误红（fail-visible，不产生假绿）
- 可选方案：维持固定等待；轮询新条目文件出现（短间隔 + 上限）后断言
- 最终选择：轮询化（约 50ms 间隔、10 秒上限）
- 选择理由：消除时序敏感，提升可重复回归脚本的机器适应性；纯测试脚本改动，无生产影响
- 影响：tests/verify-hotexit-draft-e2e.ps1

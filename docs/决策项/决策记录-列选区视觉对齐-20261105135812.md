## 决策列表

### DEC-001: 列选会话统一收敛到控制器，布局查询经 QMetaObject 按名称调用
- 阶段：方案设计（阶段 2，已批准方案）
- 背景：鼠标与键盘两条列选路径都需要逐行视觉命中；命中能力依赖 TextArea 真实布局（positionAt/positionToRectangle），存在三个候选归属：QML 层计算区间对后传控制器、控制器经 QMetaObject 查布局自算、引擎做宽度近似模型
- 可选方案：1) QML 计算区间对传控制器；2) 控制器持有会话状态、经 QMetaObject::invokeMethod 按名称调用 target 的 positionAt/positionToRectangle；3) 引擎内建"全角=2格"近似宽度模型
- 最终选择：方案 2
- 选择理由：逻辑集中单一会话（鼠标/键盘共用、行为一致），C++ 可经 test_editor offscreen 全量自动化测试（DEC-002 架构先例）；方案 3 对中文回退字体只能近似且 Tab 需另行建模；方案 1 使逻辑分裂在 QML/JS、不可单测。QQuickTextEdit 公共头未随安装布局转发，按名称调用避免编译期依赖
- 影响：控制器新增视觉会话状态与布局查询辅助；QML 层变薄（只传原始坐标）

### DEC-002: 布局查询失败的防御策略——保守无操作 + qWarning
- 阶段：方案设计（阶段 2，已批准方案的落地修正）
- 背景：原方案设想"布局查询不可用时回退字符列矩形路径"，但新鼠标接口只收 x/y、无字符位置可回退，回退在纯视觉坐标驱动下不可达
- 可选方案：1) 保守无操作并 qWarning（拖拽/按键不更新选区）；2) 强行回退字符列路径（需额外传位置、双路径语义分裂）
- 最终选择：方案 1
- 选择理由：target 恒为真实 TextArea（QML 绑定保证），失败仅属防御分支；宁可不更新也不产生错误选区；集成测试覆盖正常路径
- 影响：查询失败时列选停留在上一次有效状态；引擎字符列接口仍保留（兼容与单测契约），但不再作为运行时回退路径

### DEC-003: 移除位置式鼠标列选 API，测试改用坐标版驱动
- 阶段：方案设计（阶段 2，已批准方案）
- 背景：columnDragBegin(anchorPos,cursorPos)/columnDragUpdate(pos) 以字符位置驱动，与新视觉路径语义不符
- 可选方案：1) 移除旧接口、QML 与测试全部改走 columnDragBeginAt(x,y)/columnDragUpdateAt(x,y)；2) 保留双路径并存
- 最终选择：方案 1
- 选择理由：双路径并存会漂移（位置版无法表达视觉语义，留着即隐患）；测试驱动经 positionToRectangle 换算坐标即可保持等价断言
- 影响：test_editor bench、test_searchui 激活路径需适配；引擎静态 columnCursors 与 startColumnSelect/updateColumnSelect 保留（状态机入口 + 单测契约不变）

### DEC-004: 工作流文档写 .localdoc/，完成后同步 docs/ 既有列式编辑文档

### DEC-005: 键盘 Left/Right 在期望 x 超出当前行行末时从钳制命中位步进
- 阶段：方案设计（阶段 2，已批准方案细化）
- 背景：键盘会话期望 x 粘性；活动点落在短行上时期望 x 可能超出行末，positionAt 命中钳制到行末
- 可选方案：1) Left/Right 以钳制命中位为基准步进（Left 从行末退一格，Right 因不跨行无操作）；2) 引入虚拟空间（超出行末继续移动期望 x）
- 最终选择：方案 1
- 选择理由：与既有"Left/Right 不跨行"边界一致，实现确定；VS Code 虚拟空间超出本次范围（原需求未含）
- 影响：短行上 Right 为无操作（选区保持）；Left 退到该行最后一个字符左缘

### DEC-006: 键盘 Left/Right 增加"实际步进"防护（np != pos）
- 阶段：执行开发（阶段 5，任务 A）
- 背景：设计字面上 np==pos（文档边界 qBound 触顶，如末行行末按 Right）仍会被按"同行"处理，把期望 x 塌缩到行末光标 x，破坏粘性期望 x 且违背 DEC-005 的"无操作"语义
- 可选方案：1) 仅当"位置实际步进且未跨行"才更新期望 x；2) 按字面实现（np==pos 时同步期望 x 到命中位光标 x）
- 最终选择：方案 1
- 选择理由：保持期望 x 粘性与 DEC-005 语义自洽；触顶场景无可见选区变化
- 影响：文档边界处 Left/Right 严格无操作；期望 x 不被边界命中位污染

### DEC-008: tc008b 形态③改用 Alt+单击 + Shift+Right 构造（测试适配）
- 阶段：执行开发（阶段 5，任务 A）
- 背景：原以 `columnDragBegin(0, l2Start+55)` 构造三行字符列 [0,55) 的列选区；中文行（≈15px/字）与 ASCII 行（≈8px/字）同一 x 下视觉命中字符数必然不同，任何视觉路径都无法再现该字符列选区；该调用点在任务描述中未列出
- 可选方案：1) Alt+单击 3 行行首 + Shift+Right×55 构造逐位相同的三对选区；2) 保留旧行为（不可行，旧接口已按 DEC-003 移除）
- 最终选择：方案 1
- 选择理由：该用例目的（覆盖层多选区形态③：多对 ranges 拆段渲染）只需要"逐位相同的多对选区"，与选区来源无关；断言零改动
- 影响：tc008b 驱动方式变化，渲染断言全部保留并通过
